### What the file reports

`help select` prints that function's documentation in sections: the headline, a **See also** list of
related nodes, and **Ways to use** — the argument signatures you can actually call it with. This file
is a user's observation that the order is backwards, cross-references arriving ahead of the list of
methods, together with a narrower complaint that the one See-also entry, `partition`, is not explained
where the reader is sent.

The layout is unchanged: `help select` still prints **See also**, with `partition` in it, before **Ways
to use** — the order the file asks to reverse.

### And the case has grown stronger

The `SeeAlso` list has since expanded to **eight** entries, so the section the file already found too
prominent now occupies more of the page above the list of methods. A reader looking up `select` meets
eight cross-references before learning how to call it.

### The other half of the complaint

The file also notes that the node "points to `partition` — which is not explained there". That is the
nature of a See-also link rather than a defect, but it is why the placement matters: an unexplained
pointer is fine *after* the reader has what they came for, and confusing before it.

### Notes for whoever picks this up

This is about the ordering in the rendered help layout, not about `select`'s own node, so the change is
in the help formatter and affects every node — which makes it a small patch with a wide blast radius,
and probably worth a look at a few long pages before and after.
