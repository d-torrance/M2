Closing as a duplicate of #431 (2016), which reports the same defect and is the older of the two.

It is not obvious from the titles — #431 is filed against `Macaulay2Doc`'s own images — but its
one comment is a package called `T` with `AuxiliaryFiles => true` linking to its own auxiliary
files through `replace("PKG","T",currentLayout#"package")`, which is exactly what this issue is
about. The body there already names `SeparateExec` as what determines the layout.

Both are still reproducible on 1.26.06, and the mechanism is written up on #431: a document body
is evaluated at `installPackage.m2:688`, before `initInstallDirectory` at line 700 sets
`installPrefix` and `installLayout`, so the only layout it can see is the running M2's, and the
string it builds is then relativized against the target's. Under `SeparateExec => true` the result
is wrong by exactly the `common/` component.

Nothing here is being dismissed — the ask in this issue is the one that matters for package
authors, and #431 stays open carrying it.
