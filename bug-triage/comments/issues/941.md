Closing as fixed. On 1.26.06 both methods work:

```
i5 : gin Q

            2
o5 = ideal a

i6 : lexgin Q

            2
o6 = ideal a
```

The fix is `c670c91ab3` by @kellerlv, in PR #4322, released in 1.26.06 — and it is the patch
@aarondall wrote in this issue in 2019, down to forwarding `opts` to the inner `gin(ideal R, ...)`
call:

```
gin(QuotientRing) := Ideal => opts -> (R) -> (
     gin(ideal R, opts)
     );
```

`lexgin(QuotientRing)`, which @aarondall reported in the first comment as failing the same way,
was fixed in the same commit, and both are now covered by TEST blocks — along with the option
forwarding itself, which is what was broken: each method was declared without `opts ->`, so
dispatch passed the option table in place of the ring argument.
