This is unbounded recursion rather than a slow computation, and with these degrees the retry it
is stuck in can never succeed.

`getRandomLinearForms` ends with a retry that has no bound and no change of strategy
([`RandomPoints.m2:461-467`](https://github.com/Macaulay2/M2/blob/development/M2/Macaulay2/packages/RandomPoints.m2#L461-L467)):

```m2
    if (opts.Verify) and (#formList > 0) then (
        J1 := jacobian ideal formList;
        val := min(d, #formList);
        if (rank J1 < val) then (
            ...
            return getRandomLinearForms(R1, L1, opts);
        );
    );
```

Running the reporter's example under `--script`, where the default `recursionLimit` is 300, it
stops in seconds with `recursion limit of 300 exceeded` instead of hanging, and a frame census of
the backtrace has `RandomPoints.m2:467` in it 77 times. Raising `recursionLimit` to 10000 just
moves the wall, so nothing is making progress between retries.

The reason the guard can never pass is the degree vector. In `kk[x,y, Degrees => {2,1}]` the
degree-one graded piece is one-dimensional:

```m2
i1 : kk = ZZ/(nextPrime 10^4); A2 = kk[x,y, Degrees => {2,1}];

i3 : basis(1, A2)
o3 = | y |

i4 : apply(4, i -> random(1, A2))
o4 = {-2169*y, 109*y, 4959*y, -3299*y}
```

Every `random(1, A2)` is a scalar multiple of `y`, so the Jacobian of any number of these forms
has rank 1, while `val` is `min(d, #formList)` = 2. `rank J1 < val` therefore holds on every
attempt, forever.

The control is the same construction with standard degrees, where the only thing that changes is
the degree vector:

```m2
i5 : B2 = kk[x,y];

i6 : basis(1, B2)
o6 = | x y |

i7 : rank jacobian ideal apply(2, i -> random(0,B2) + random(1, B2))
o7 = 2
```

Rank 2, guard passes, first try.

Two things this also accounts for:

- **`Homogeneous => false` not helping**, which the reporter noted. The linear forms still come
  from `random(1, R1)`, so they are still multiples of `y`.
- **It is not the Gröbner engine.** `gb I` on the same ideal in the same ring returns normally;
  only the `RandomPoints` retry loop is affected.

So the fix is presumably some combination of bounding the retry and not requiring a full-rank
Jacobian from forms drawn out of a graded piece too small to provide one. I have not tried to
write it, and there may be a reason the `Verify` path wants that rank condition that is not
visible from here.
