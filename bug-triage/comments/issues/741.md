### The reported error was fixed in 2018

`a02c1eb3e2`, "fix res for poly rings of poly rings", is one line — `Join => false` added to the
monoid that `resolutionByHomogenization` builds. Both rings in the report resolve on
1.26.06-40-gd8e86d689d:

```m2
i1 : kk = QQ; A = kk[a,b,c,d]; B = A[x,y,z, Join=>false]; I = ideal(x-a-1, y-2, z-3);

i5 : betti res I

            0 1 2 3
o5 = total: 1 3 3 1
         0: 1 3 3 1
```

That fix survived the move of `res.m2` into `Complexes`; the line is now
`Complexes/FreeResolution.m2:526`.

### What is still open is the multigrading

> A related issue is that we might save some time by flattening a resolution with a
> multigrading, rather than just reverting to resolution-by-syzygy. What do you think?

Still exactly true, and the guard is nameable. `resolutionByHomogenization` refuses anything
that is not singly graded (`Complexes/FreeResolution.m2:511-515`):

```m2
if isHomogeneous M or
    not isCommutative R or
    not degreeLength R === 1
then return null;
```

The two rings in the original report happen to sit on either side of that test, which makes the
example a demonstration of the *remaining* issue rather than of the fixed one:

| | `degreeLength` | `Strategy => Homogenization` |
| --- | ---: | --- |
| `A[x,y,z, Join=>false]` | 1 | resolves |
| `A[x,y,z]` | 2 | **refused**, falls back to `Strategy => Syzygies` |

So a tower with the default `Join` — the ordinary case — still reverts to resolution-by-syzygy,
which is the cost @DanGrayson proposed avoiding and @mikestillman was asked about.
