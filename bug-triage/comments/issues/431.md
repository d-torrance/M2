Wrong by exactly the `common/` component, which is all that separates the two layouts here:
`Layout#1#"package"` is `share/Macaulay2/PKG/`, `Layout#2#"package"` is
`common/share/Macaulay2/PKG/`.

**The binding constraint looks like an ordering.** `installPackage` loads the documentation at
`installPackage.m2:688` (`loadPackage(..., LoadDocumentation => true)`) and only then calls
`initInstallDirectory` at line 700, which is what sets `installPrefix` and `installLayout`. So when
the `IMG` or `HREF` in a document body is evaluated, the target of the install in progress is not
yet known. Printing those globals from inside a package body across the two installs above:

```
installPrefix = /home/.../.Macaulay2/local/     installLayout = share/Macaulay2/PKG/
installPrefix = null                            installLayout = null
```

Stale on the first, null on the second, and neither time the directory being installed into. The
only layout a document body can see is `currentLayout`, the running M2's — which is the mismatch
this issue describes. The string is then relativized against the *target*: `toURL String`
(`hypertext.m2:63`) does `relativizeFilename(htmlDirectory, pth)`, and `htmlDirectory` comes from
the install layout. One layout in, a different one out.

**`TO` links escape it because they never build a string.** `htmlFilename`
(`installPackage.m2:86-101`) reads `installLayout` and returns a `(prefix, tail)` pair, which
`toURL(String, String)` resolves when the page is written — the source calls that one "this is the
good one". `getStyleFile` (`m2/html.m2:10`) does the same through `locatePackageFileRelative`,
which takes *a function from layout tables to paths* rather than a path, which is why the KaTeX and
prism links are right under both settings.

**And the deferred form is already reachable from a document body — almost.** `new HREF from List`
(`hypertext.m2:267`) accepts "a string or a sequence of 2 strings", and `html HREF`
(`html.m2:166`) calls `toURL first x`, so a pair dispatches to the two-argument method. What is
missing is not a link type; it is that nothing evaluated at document time knows the target layout
to build the pair from.

Which puts the whole thing back on line 688 versus line 700. `initInstallDirectory` (line 65) reads
only `opts.InstallPrefix` and `opts.SeparateExec` and does not need the loaded package, so it looks
movable — and if it ran first, a document body could write
`HREF {(installPrefix, replace("PKG", "T", installLayout#"package") | "a.txt"), "a.txt"}` and the
existing machinery would relativize it correctly for whichever layout was being installed. I have
not tried moving it and something may well depend on the current order, but that is the constraint
to attack rather than anything about `HREF`, `IMG` or `toURL`.
