Fixed in 1.20, by @jkyang92, in #2344 — and the fix cites this issue in the source, at
`m2/examples.m2`:

```m2
-- null out all symbols in the private dictionary, otherwise those values leak
-- See bug #2330 for details.
scan(values User#"private dictionary", s -> (if isMutable s then s <- null));
```

with the same treatment for `OutputDictionary` a few lines down. Nothing closed the issue.

Measured on 1.26.06: 10,000 `capture` calls grow RSS by 428 kB in total, and flat rather than
climbing — a shorter 1,200-call run ended 30 MB *below* where it started, the collector having
released memory along the way. Against the ~0.5 MB/s reported here, that is the leak being gone
rather than merely smaller. The control from the original report, the same work without `capture`,
grows nothing.

Closing on the leak this reports. Separate from it: the idea raised here twice, most recently in
2023, of using `capture` as a front-end leak detector — that never was what this issue tracked, and
would be worth its own issue if it is still wanted.
