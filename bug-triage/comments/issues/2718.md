Answering @pzinn's question about why we cannot invert `ZZ` matrices, since it went unanswered: there
are two separate reasons, and one of them is that working code exists and is not wired up.

First, the measurements, on the matrix posted here on 1.26.06 (`det A` is 1, so it really is
unimodular):

```
A^-1                      out of memory at 3.9 GB after 151 s
(transpose A)^-1          0.018 s
promote(A, ZZ[])^-1       0.019 s
promote(A, QQ)^-1         0.014 s
```

so all three of the contrasts reported above still hold.

**Why it never reaches the engine.** `inverse Matrix`
([`matrix1.m2:623-630`](https://github.com/Macaulay2/M2/blob/development/M2/Macaulay2/m2/matrix1.m2#L623-L630))
uses the engine only when `hasEngineLinearAlgebra` is true for the ring:

```m2
if hasEngineLinearAlgebra ring m and isBasicMatrix m then basicInverse m
else ((quo,rem) := quotientRemainder(id_(target m), m); ...)
```

`hasEngineLinearAlgebra` is `false` for `ZZ` and `true` for `QQ`, `RR_53`, `CC_53` and `ZZ/32003`.
So `ZZ` takes the `quotientRemainder` branch — a division computation whose cost depends on the pivot
structure, which is why the upper-triangular transpose finishes instantly on the same data, and why
promoting to `QQ` or to `ZZ[]` also escapes.

**Why forcing the engine does not help yet.** `rawLinAlgInverse` on a dense mutable `ZZ` matrix gives
the error you found. The generic template at `mat-linalg.hpp:115` is not the only culprit:
`inverse(const DMatZZGMP&)` at `:659` is itself a stub that throws. But 111 lines below, at `:770`,
there is a real implementation:

```cpp
inline bool inverse(const DMatZZ& A, DMatZZ& result_inv)
{
  M2::ARingZZ::Element den(A.ring());
  bool result = fmpz_mat_inv(result_inv.fmpz_mat(), &den.value(), A.fmpz_mat());
  if (!fmpz_is_pm1(&den.value())) result = false;
  return result;
}
```

FLINT's `fmpz_mat_inv`, and it already rejects non-unit denominators — exactly the semantics wanted
for inverting over `ZZ`. So the pieces for the fast path are in the same file as the stub that throws;
what is missing is `DMatZZGMP` reaching it and `hasEngineLinearAlgebra ZZ` becoming true.
