They were disabled in 2017 over API drift in fflas-ffpack, and the drift has since partly
reversed.

Both functions currently open with `(void) A;` and an `#if 0` that swallows the whole body, so
each returns `nullptr` without looking at its argument —
`Macaulay2/e/interface/mutable-matrix.cpp:1006` and `:1040`. @DanGrayson disabled them in
[`0b835d6ef6`](https://github.com/Macaulay2/M2/commit/0b835d6ef6a08b418d93794e123c5048066fc8dc)
(2017-06-09), a commit whose subject is *"make libraries static, ..."* — which is why looking for
the disabling by name does not find it. The `FFPACK::CharPoly` call had already been commented out
before that commit; the minpoly call was still live, and went behind the `#if 0` with the note it
still carries:

```c++
  // this is in ffpack 2.3 but not in 2.2, and it might be the wrong name now, was MinPoly before
```

Against fflas-ffpack 2.5.0 both entry points exist again, but only one of the two call sites would
compile as written:

* `FFPACK::Protected::Hybrid_KGF_LUK_MinPoly(F, minP, N, A, lda, X, ldx, P, ...)` is at
  `ffpack/ffpack.h:1184` with the signature the disabled code passes, and there is a plain
  `FFPACK::MinPoly(F, minP, N, A, lda)` at `:1137` besides.
* `FFPACK::CharPoly` at `:1003` now takes a polynomial ring and a `PolRing::Element` (or a
  `std::list` of them) rather than a field and a `std::vector` of field elements, so that one needs
  rewriting rather than just un-`#if`-ing.

The only caller of either in the tree is the undistributed `FastLinearAlgebra`.

Worth connecting to #2897: @mikestillman suggested there that eigenvalues over a finite field would
be better computed from the characteristic or minimal polynomial. These are the two functions that
would supply it.
