Closing this as won't-fix on the general point, while recording that the specific clash is still
live and is a package bug rather than a language one.

### Redefining methods is deliberate

The proposal here was *"print a warning message when a method function is redefined."* Installing
a method over an existing one is a normal and useful thing to do in Macaulay2 — interactively, and
when a package extends behaviour defined elsewhere — so a warning on redefinition would fire
constantly on correct use. There is no way to make that check quiet without knowing intent, and
the cases where intent is obvious are exactly the cases nobody needs warning about.

### The example, though, is still there and still silent

Both definitions of `matrix(BettiTally, ZZ, ZZ)` are present today, and which one you get is
decided by load order:

```m2
i1 : R = ZZ/101[a,b,c]; B = betti res ideal(a,b,c);

i3 : needsPackage "BoijSoederberg";

i4 : ring matrix(B,0,3)

o4 = ZZ

i5 : needsPackage "RandomMonomialIdeals";

i6 : ring matrix(B,0,3)

o6 = RR
     53
```

No warning at any point, and the same call with the same arguments returns a matrix over a
different ring depending on what else happens to be loaded.

That is worth fixing, but in `RandomMonomialIdeals` rather than in the interpreter. Its version is
a copy of `BoijSoederberg`'s with one line changed and the original left commented out —

```m2
     --M := mutableMatrix(ZZ,r,c);
     M := mutableMatrix(RR,r,c);
```

— so it is not extending a shared method or specialising it for its own types; it is globally
replacing another package's method with one that answers differently. A local helper under its own
name would do everything it needs and would not reach outside the package.
