Half the subject of this issue has been settled since it was written, which is worth
knowing before anyone starts on the automation.

This asks to automate the tests in two files from the pre-GitHub `bugs/` tree. Both were
looked at during the sweep of that tree ([#36](https://github.com/Macaulay2/M2/issues/36)):

**`bugs/dan/0-final-check-interactive-input-behaviour`** was verified and came out clean —
all four sections check out on 1.26.06. Its named problem, readline not discarding partial
input after `SIGINT`, is #813, closed: `///asdf`, `"asdf`, `1 +` and `-*` each followed by
Ctrl-C all return to a usable prompt and evaluate the next expression. Blank lines inside
multi-line input are tolerated, which is #820, also closed, and #820 records that it became
possible once #813 landed. Multiple statements per line match the file's transcript and
parsing recovers. The `{* *}` cases are moot, since block comments are now `-* *-`.

One thing from that check bears directly on automating it: **piped stdin does not recover
after a syntax error, and a pty does.** The same input that fails through a pipe recovers
fine under `expect`. So a test harness that pipes into M2 will report failures that a user
at a terminal never sees — which is presumably part of why these were left as a manual
checklist in the first place.

**`bugs/dan/0-final-checks-before-distribution`** no longer exists. It was deleted before
[`d2c8d27826`](https://github.com/Macaulay2/M2/commit/d2c8d27826) removed the rest of the
tree in 2024, so it is not among the 857 files catalogued there and its content is only in
git history.

None of that automates anything, so the ask here is untouched. But the interactive-input
file is now known-good rather than unknown, its two underlying issues are closed, and
anybody writing the harness should reach for a pty rather than a pipe.
