### `hh^(p,q)` works, and did when this was filed

That last line succeeded. It ends in a semicolon, so its output was suppressed and the screenshot
shows nothing after it — which is why the issue reads as though both attempts failed.

```m2
i1 : V = Grassmannian(1,3, CoefficientRing => QQ);  X = Proj(ring V / V);

i2 : hh^(0,0)(X)

o2 = 1

i3 : HH^0(tangentSheaf X)

      15
o3 = QQ
```

`hh(Sequence, ProjectiveVariety)` is not new: it dates to 2005 and was already at
`m2/varieties.m2:461` in November 2019, a few days before this was filed. It lives at
`Varieties.m2:784` today.

### What is missing is the functor, which is what @DanGrayson asked for

His reply above — *"That would be a good method to add, especially if it could be made into a
functor"* — names the half that still does not exist. `hh^(p,q)` returns the Hodge **number**;
there is nothing that returns the Hodge cohomology **group**.

`HH^(0,0)(X)` fails because it dispatches to `cohomology((0,0), X)` and finds no method. Every
`cohomology` method in the tree takes a `ZZ` cohomological degree —
`(cohomology, ZZ, ProjectiveVariety, CoherentSheaf)`,
`(cohomology, ZZ, NormalToricVariety, CoherentSheaf)` and so on — so the missing piece is
`cohomology(Sequence, ProjectiveVariety)`, exactly parallel to the `hh` method that already exists.
Nothing elsewhere in the distributed packages provides it: `HodgeIntegrals` is about Hodge integrals
on moduli of curves, `ExteriorExtensions` has the Hodge star operator, and the "Hodge-special"
fourfolds in `SpecialFanoFourfolds` are a classification, not a cohomology theory.

and made the issue unfindable for anyone searching for Hodge cohomology. Nothing else about the
