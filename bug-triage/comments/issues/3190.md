Each failure in this thread has an answer:

**The `readline` one you started with.** `5fd028f22e`, *"Build readline w/ curses support"*
([PR #4124](https://github.com/Macaulay2/M2/pull/4124), merged 2026-02-10), adds `--with-curses` and
`SHLIB_LIBS=-lcurses` to M2's readline build. Its commit message quotes the same error you hit:

```
awk: symbol lookup error: .../libreadline.so.8: undefined symbol: UP
```

Your own diagnosis was right — `UP` is a terminfo symbol, and readline had to be linked against
curses.

**The prerequisites and tooling.** `ninja`, `blas-devel`, `gdbm-devel`, OpenBLAS and GMP not being
found are all pinned down now by the RHEL Dockerfile added in
[PR #3461](https://github.com/Macaulay2/M2/pull/3461) *"Autotools build updates for RHEL 8"*
(2024-10-19), and maintained since — including a commit that adds `ninja-build` to the RHEL
prerequisites, which is exactly the obstacle you ran into.

One correction for the record, since it may save someone a wrong turn: @jkyang92 asked whether
factory could be passed `--with-readline=no`. Factory does not link readline — there is no mention
of it in `M2/libraries/factory/Makefile.in`, then or now. What happened is that `awk`, invoked
during factory's `config.status`, picked up M2's own freshly-built `libreadline.so.8`, which is what
the curses fix repairs.
