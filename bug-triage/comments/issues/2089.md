Fixed in 1.25.11. The guard went in exactly where @DanGrayson's backtrace pointed —
`rawSetRandomInteger` in `e/interface/random.cpp` now tests the height before handing it to
`mpz_urandomm`:

```cpp
  if (maxN == nullptr) maxN = maxHeight;
  if (mpz_cmp_si(maxN, 0) <= 0)
    throw exc::engine_error("expected a positive height");
```

That was `a96e31463a`, shipped in #3893; #3481 had already done the same for `random(QQ)`. Both
appear in this issue's timeline as cross-references, so it was fixed under this number without
anyone closing it.
