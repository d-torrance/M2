On the `ncursesw` idea from above — it would not have helped, and it's worth recording why. On a
distro that splits the terminfo library, `tgoto` is not in ncurses at all: it is in `libtinfo`, which
is already in the search list, and `libncurses.so.6` pulls it in via `DT_NEEDED`. Arch folds the term
library into ncurses instead and ships `libncurses.so` → `libncursesw.so`, so `-lncurses` resolves
`tgoto` there too. Either way the existing `curses tinfo ncurses` list is sufficient, which matches
@PhyX-Meow finding that adding `ncursesw` changed nothing.

same args as in PKGBUILD, but fails if running by `makepkg`"* — pointing at the packaging environment,
which is where it would need to be chased.
