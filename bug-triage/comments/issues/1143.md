Fixed. The guard that raised this was removed by
[`def6c8e965`](https://github.com/Macaulay2/M2/commit/def6c8e965) (@mahrud, 2020-11-16,
*"hookify primaryDecomposition and associatedPrimes"*), in
[#1385](https://github.com/Macaulay2/M2/pull/1385), merged 2020-12-02.

The example from the body, and two that actually decompose:

```m2
i1 : R = GF(2,3)[x];

i2 : primaryDecomposition ideal(x^2+1)

             2
o2 = {ideal(x  + 1)}

i3 : associatedPrimes ideal(x^2+1)

o3 = {ideal(x + 1)}
```

which is right — `x^2+1 = (x+1)^2` in characteristic 2, so the ideal is already primary.

```m2
i4 : S = GF(2,3)[x,y];

i5 : primaryDecomposition ideal(x^2*y, y^2)

                       2   2
o5 = {ideal y, ideal (y , x )}

i6 : T = GF(9)[u,v];

i7 : primaryDecomposition ideal(u^2-v^2)

o7 = {ideal(u + v), ideal(u - v)}
```

So the manual workaround in your report — flattening to `ZZ/2[a,x]/ideal(a^3+a+1)` by hand — is no
longer needed.

The same pull request also fixed [#1017](https://github.com/Macaulay2/M2/issues/1017), which was
`radical` failing on the same guard.
