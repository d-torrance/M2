Carrying over two things from #3112, which is being closed as a duplicate of this issue. Its body
and @DanGrayson's 2018 comment here are the same proposal — remove `=distributed-packages` and
distribute everything in the directory — but #3112 raised two points that are not recorded here.

**A recurring cost that this issue does not mention.** Every new package is appended to the end of
`=distributed-packages`, so whenever two package-addition PRs are open at once, the second one
conflicts after the first merges. That happens on a schedule rather than by accident, and it is the
symptom that prompted #3112.

**A cheaper fix than removing the file.** Alphabetising the list would eliminate that collision
without settling whether the file should exist at all — new entries would be distributed through
the file instead of piling up at one line. That is worth separating from the removal proposal,
because it can be done independently and immediately.

Two facts that bear on how safe that is: the list is 299 entries, and its order is **not** a
topological sort of the dependency graph — there are 110 edges running the wrong way already, and
only `Style`, `FirstPackage` and `Macaulay2Doc` are declared prerequisites. So the current order is
not carrying dependency information that alphabetising would destroy.
