Closing this: the rename has not happened and is not planned. `GeneralOrderedMonoid` is still
`m2/monoids.m2:188`, a direct subtype of `OrderedMonoid`, and no `OrderedFreeMonoid` was added —
the associative-algebras work this was meant to support went ahead without either change.

Two notes for anyone who reopens the question rather than the issue.

Somebody did start it. `AssociativeAlgebras.m2` has a `FreeMonoid` type and a `freeMonoid`
method under the comment `-- Toying with adding FreeMonoids`, but they sit below the file's
`end` line and so are never loaded; `isGlobalSymbol "FreeMonoid"` is false.

And the conflation this issue is about is load-bearing, not merely untidy:

```m2
i1 : class monoid (QQ[x,y])

o1 = GeneralOrderedMonoid

i2 : class monoid (QQ <| x,y |>)

o2 = GeneralOrderedMonoid
```

One type serves both the commutative and the free case, so renaming it to
`OrderedFreeCommutativeMonoid` today would misname the noncommutative one rather than finish
the job.
