The behaviour is still there, but the cause turns out not to be the dependency — which matters,
because as written this sends the next reader looking for propagation code that does not exist.

Nothing propagates. With a throwaway `OptTwo` declaring `OptionalComponentsPresent => false` and an
`OptOne` that pulls it in, `OptOne` comes out `true` under `PackageImports` and `true` under
`PackageExports` alike, on 1.26.06-40-gd8e86d689d. `check "OptTwo"` skips; `check "OptOne"` runs.

What forces `false` is `m2/packages.m2:360`:

```m2
if opts.OptionalComponentsPresent === null then opts = opts ++ {OptionalComponentsPresent => opts.CacheExampleOutput =!= true};
```

`NumericalSchubertCalculus.m2:36` sets `CacheExampleOutput => true`, and that alone gives it
`OptionalComponentsPresent => false` and the silently skipped tests. So the ask here — that a
package inherit its dependency's optional-component status — is real and unimplemented, but the
symptom you saw came from somewhere else.

One thing worth acting on separately: the workaround has drifted. Lines 1–4 of
`NumericalSchubertCalculus.m2` are a verbatim copy of lines 1–4 of `PHCpack.m2`, and the copies no
longer agree — `PHCpack` has required `phc >= 2.4.77` since
[`ad6ea46aee`](https://github.com/Macaulay2/M2/commit/ad6ea46aee) (2020-06-26), while the copy still
requires `>= 2.3.80`. With a phc in between, `NumericalSchubertCalculus` declares its components
present and runs tests against a `PHCpack` that has declared them absent.
