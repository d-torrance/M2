Still current on 1.26.06, and the diagnosis above is right in every particular. `#` on a `Matrix`
returns its number of hash-table keys — `{source, ring, RawMatrix, target, cache}` — which is **5
for every matrix**, so `Code.m2:840` builds a five-variable ring no matter what the ideal is:

```m2
i4 : numcols mingens I

o4 = 6

i5 : # (mingens I)

o5 = 5

i6 : lyubeznikResolution I
stdio:6:19:(3):[1]: error: index 5 out of bounds 0 .. 4
```

sits further down the same file, as #2847.** `git grep` for `#` applied to `mingens` across
`M2/Macaulay2` returns exactly two hits —

```
SimplicialComplexes/Code.m2:840   R := QQ(monoid[vars(0..#(mingens I)-1)]);   -- lyubeznikResolution, this issue
SimplicialComplexes/Code.m2:888   A := QQ(monoid[vars(0..#(mingens I)-1)]);   -- scarfChainComplex, #2847
```
