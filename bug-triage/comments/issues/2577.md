Fixed in 1.21. The malformed option is now rejected rather than accepted:

```m2
i1 : R = QQ[x, y, WeylAlgebra => x];
     error: WeylAlgebra: encountered extra homogenizing variable
```

The guard is in `processWeyl` (`m2/monoids.m2`), from `f63063383e`, "simplified argument processing
for monoid", which merged in #2600.

Worth spelling out why this stayed open, since the dates look odd: that commit is dated five days
*before* this issue was filed, but it merged a month *after* — so the fix existed on a branch while
the report was written, and @DanGrayson's transcript was from 1.20.0.1, which predates it. Nobody came
back to close it.

The second example here has also changed, and I cannot tell whether for the better:

```m2
W = QQ[x, y, dy, s, WeylAlgebra => {{1, 2}}];
eliminate(ideal(x*y*dy, x^2, 2*y^2*dy^2+3*y*dy, y*dy+s+1), {y, dy})
```

now gives `ideal(2*s^2+3*s+1, x*s+x, x^2)` where this thread recorded `ideal(s+1, x^2)`. Since the
expected answer was never stated, that is a change rather than a fix — @mahrud, if it still looks
wrong, it is probably worth its own issue, given it was your evidence that other Weyl algebra
functionality had fallen through the cracks.
