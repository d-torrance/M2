The defect reported here is fixed, so this issue is being retitled to the question that is
actually still open.

**`solve` now raises an error instead of returning a wrong answer.** The same input gives

```
error: solve not implemented over ring R
```

from `m2/mutablemat.m2:216`. That is what @pepperhdj and @dylanpeifer identified in 2020 —
[#1141](https://github.com/Macaulay2/M2/pull/1141) — and it is the change @DanGrayson asked for
above: *"maybe the bug is for it not to give an error message."*

**What is left is the generalisation, and it is an offer nobody answered.** @mahrud wrote in 2019:

> Still, when the system is solvable using syzygies, generalizing `solve` should be easy. I can
> make a PR to do that if you'd like.

@DanGrayson put that to @mikestillman, and the thread stops there. @dylanpeifer restated it in 2020
— *"Generalizing to use syzygies might still be useful"* — and that also went unanswered. The
working method is in the issue body above: `syz (A | v)` finds the solution that `solve` will not.

So the title has been changed from *"Bug in solve"* to *"solve should use syzygies over rings where
it is not implemented"* — the wrong answer is gone, and what this tracks now is a capability that
was offered and never taken up. The new title quotes the error text so that searching for it lands
here. Nothing else about the issue has been altered.
