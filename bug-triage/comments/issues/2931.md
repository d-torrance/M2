Still happens on 1.26.06, and it narrows further than the thread has it: the ordinary constructor
is fine, so this is specific to `new MutableMatrix from`.

```m2
i1 : entries new Matrix from matrix{{span(0)}}

o1 = {{[0,-0]}}

i2 : entries new MutableMatrix from matrix{{span(0)}}

o2 = {{[NotANumber,NotANumber] (an empty interval)}}

i3 : entries mutableMatrix matrix{{span(0)}}

o3 = {{[0,-0]}}

i4 : entries new MutableMatrix from matrix{{span(1)}}

o4 = {{[1,1]}}
```

`mutableMatrix` round-trips the zero interval correctly, which is both a workaround and an argument
against the guess in the second comment — if the sparse representation were dropping the zero and
failing to rebuild the interval, `mutableMatrix` would fail the same way. Whatever is wrong is in
the `new ... from` path rather than in the storage.

One thing worth knowing before anyone tries to reproduce it: both matrices now **print as `0`** at
the top level, so the difference is invisible unless you ask for `entries`. That was not the case
when this was filed.
