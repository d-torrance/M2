Closing as not planned. ppc64 still builds, but it is not a Debian release architecture, so this is
not worth holding open — nothing has happened on it in four years and there is no release riding on
it.

One thing worth leaving on the record, because it distinguishes this from the other big-endian
failures on this tracker. The signature here is thread-related rather than endian-related: repeated

```
thread_monitor Resource temporarily unavailable in pthread_create
```

followed by SIGSEGV and `corrupted double-linked list`. That is thread creation failing under a
resource limit and the failure then being handled badly — not a wrong answer, as in #2205 where
`minimalBetti` disagreed with `betti res` on mips64el, or #2162 where F4 returns a different basis on
s390x. So if ppc64 ever becomes release-relevant again, or if the same `pthread_create` exhaustion
turns up somewhere that matters, this is the thread to pull rather than the endianness ones.
