### Why comparing Gröbner bases is not faster: it is the same reduction

`isSubset` bottoms out in `issub`, at `m2/modules.m2:312`:

```m2
issub = (f, g) -> f === g or ring f === ring g and tryHooks(ContainmentHooks, (f, g),
    (f, g) -> -1 === rawGBContains(raw gb g, raw f))
```

and the commented-out alternative is `m2/gb.m2:229`:

```m2
GroebnerBasis == GroebnerBasis := (G1, G2) ->
    -1 === rawGBContains(raw G1, raw generators G2) and
    -1 === rawGBContains(raw G2, raw generators G1)
```

Both are two calls to `rawGBContains`, both compute a Gröbner basis of each side, and both
reduce one side's generators against the other's basis. The *only* difference is which
matrix gets reduced: `isSubset` reduces the original generators, while `gb I == gb J`
reduces `generators G2`, the Gröbner basis generators — which are normally more numerous.
So if anything the commented-out version does slightly more work, which is a plausible
reason it was never switched on.

Measured on a 6-variable pair of equal ideals given by different generators, from cold:

| | |
| --- | --- |
| `isSubset(I,J) and isSubset(J,I)` | 0.00056 s |
| `gb I == gb J` | 0.00050 s |

Parity, and both `true`. That is one small example and the mechanism above is the real
evidence; but nothing in the mechanism suggests a case where the difference would grow.

### @eisenbud's question, which is the more useful half

> and why wouldn't `gens gb I == gens gb J` work for inhomogeneous ideals too?

Inhomogeneity is not the obstacle — over a global order I could not break it (23 pairs of
equal ideals over `QQ`, `ZZ/32003` and `ZZ`, inhomogeneous ones included, no disagreement).
The obstacle is that `gens gb` is not canonical, because the basis it returns need not be
reduced:

```
i1 : L = QQ[x,y, MonomialOrder => Lex, Local => true];

i2 : I = ideal(x,y);  J = ideal(x+y,y);

i3 : I == J
o3 = true

i4 : gens gb I
o4 = {y, x}

i5 : gens gb J
o5 = {y, x+y}

i6 : gens gb I == gens gb J
o6 = false
```

`x+y` still contains `y`, which is a leading term of the other basis element, so this is a
minimal standard basis rather than a reduced one. Comparing the *matrices* therefore reports
two equal ideals as unequal — a false negative, and a correctness bug rather than a slowdown.

Worth being precise that this does **not** condemn the commented-out line: `gb I == gb J`
compares the Gröbner basis *objects* via `rawGBContains`, and it correctly returns `true` on
the example above. It is the matrix comparison specifically that is unsafe.
