### What is lost

Checking the three results against the untrimmed sum:

```m2
i1 : R = ZZ[a,x,y];
     I = ideal(a^2+5, (1+a)*x - 2*y, 3*x - (1-a)*y);
     J = ideal(x*y - x^2 - y^2 - 1);
     K = ideal(3,1-a);
     S = I+J+K;                                    -- untrimmed

i6 : S == trim(trim(I+K)+J)

o6 = true

i7 : S == trim(trim(I+J)+K), S == trim(I+J+K)

o7 = (false, false)

i8 : (y^2+1) % S == 0, (y^2+1) % trim(I+J+K) == 0

o8 = (true, false)
```

`y^2+1` is in the ideal and is not in the trimmed result, so the trimmed ideal is properly
contained in its input. Note `trim(I+J+K)` is wrong on its own — the association order in the
report is a way of stumbling into this, not the cause.

### One thing separates the good runs from the bad

Computing a complete Gröbner basis **before** calling `trim` makes it correct, both here and in
#4095, which reports the same defect in one variable:

| | `trim` on a fresh ideal | `gens gb I` first, then `trim` |
| --- | --- | --- |
| this issue, `I+J+K` | `\| 3 x-y a-1 \|` — wrong | `\| 3 x-y a-1 y^2+1 \|` — correct |
| #4095, `ideal(x^2+x+1, x^4+x^3+x^2+x+1)` | `\| x+1 \|` — wrong | `\| 1 \|` — correct |

(`mingens` first does *not* help; it has to be the full basis.) So `gens gb I` before `trim I`
is a workaround for anyone hitting this today.

That the partial basis is what breaks it is by design, and stated in the source at
`M2/Macaulay2/m2/matrix2.m2:228`:

```m2
-- we preserve the ambient free module of which M is subquotient and try to minimize the
--   generators and relations without computing an entire gb
mingb := m -> gb (m, StopWithMinimalGenerators=>true, Syzygies=>false, ChangeMatrix=>false);
```

Reading minimal generators off a min-gens-stopped basis is sound over a field. Over **Z** it is
not, which is what the table above measures. The only ZZ special case in `trim` is at line 281:

```m2
if ring M === ZZ then (
     LLLBases := needsPackage "LLLBases";
     ...
```

a strict equality, so `ZZ[a,x,y]` and `ZZ[x]` do not match it and take the field path.
