Closing: the workaround @moorewf described in the last comment was submitted and merged —
[PR #2879](https://github.com/Macaulay2/M2/pull/2879), *"Associative Algebras Duplicate Large Block
Temporary Fix"*, commit `8e5e99eb39`, written 2023-06-13 (the day he asked) and merged 2023-08-29.
Nobody came back to say so here.

It does what he said and a little more: `f4Allowed` in `AssociativeAlgebras.m2` is narrowed so that
any coefficient ring other than the prime field falls back to the Naive algorithm instead of `F4`
or `F4Parallel`, and `skewPolynomialRing` now caches its skew-commuting relations as a known
Gröbner basis, so no NC GB is computed there at all.

The reporting example completes on 1.26.06, three runs for three, printing

```
Warning:  F4 Algorithm not available over current coefficient ring or inhomogeneous ideal.
Converting to Naive algorithm.
```

— that is, the `NCF4::generalReduceF4Row` path in the stack trace above is no longer entered.

**What this does not fix is the corruption itself.** The PR is titled "Temporary" for a reason: F4
over a GC-allocated ring is presumably still unsafe, it is now merely unreachable by default. If
that is worth tracking, it is a different issue from this one, which was about a build failure in
the `oppositeRing` example.
