Closing as a duplicate of #701, which @mahrud identified above — but the two parts of this issue
that #701 does not have have been carried over there rather than closed with it.

**What is already #701.** Its body is the ghost-package problem in this thread — *"a package may be
present in the packages directory but not on the list of packages to be distributed... The error
will not be discovered by our tests"* — which is `SchurVeronese` and `NCAlgebraV2` exactly. And
@DanGrayson proposed option 1 there on 2018-04-14, six years before this issue:
*"We should remove the list `=distributed-packages` and distribute all packages found in the
directory `packages`."* #701 is the older issue and already carries a summary of where that work
stands.

**What has been carried over.** Two things here are not on #701 and are worth keeping: the
merge-conflict symptom that motivates this issue — two concurrent new-package PRs colliding because
every addition lands at the end of the file — and option 2, alphabetising the list, which fixes that
symptom on its own without settling whether the file should exist at all.

Status of the sub-thread, for the record: `SchurVeronese` **was** fixed and is now in
`=distributed-packages`, so its documentation is reachable. `NCAlgebraV2.m2` is still a file in
`packages/`, still absent from the list, and not in `undistributed-packages/` either — it remains
the stray, and it is tracked on #701.
