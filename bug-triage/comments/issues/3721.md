Reproduces on 1.26.06, exactly as reported — the option drops a generator that the unrestricted
computation keeps:

```
gb(H, StopWithMinimalGenerators => true)  ->  | -1 |        gens gb H  ->  | -1 x+1 |
                                              | 1  |                       | 1  0   |
```

Worth adding, because it explains why this is hard to adjudicate: **there is nothing to check the
behaviour against.** The only prose describing this option anywhere in `Macaulay2Doc` is commented
out. `ov_ringmaps.m2:491-499` has the whole node behind `--`, including the sentence that would
settle it —

> specifies that the computation should stop as soon as a complete list of minimal generators for the
> submodule or ideal has been determined

— and it refers the reader to `[gb, StopWithMinimalGenerators]` "for details", which that
commented-out block is the only trace of.

So a user meeting this option has nothing to read, and there is no written contract to measure the
engine against. Documenting it is separable from deciding whether the engine is wrong, and it is
probably the first step either way.
