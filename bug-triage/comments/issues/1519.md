The failure reported here is fixed, though not in the way the title asks for.

```m2
i1 : ideal 4 : ideal 6

o1 = ideal 2
```

which is right — `{n : 4 | 6n} = (2)`.

The fix is [`549828338a`](https://github.com/Macaulay2/M2/commit/549828338a) (2020-11-23,
*"doc updates in Colon"*), which added a `Number` overload beside the existing one:

```m2
quotient(Ideal,  Number)      :=
quotient(Ideal,  RingElement) := Ideal  => opts -> (I, f) -> quotient(I, ideal f, opts)
```

now at `Saturation.m2:146-147`, after the `Colon` package was renamed. It reached `development`
through [#1385](https://github.com/Macaulay2/M2/pull/1385) — worth noting that branch was opened
before this issue was filed and merged after it, so the PR's own dates are misleading; the commit
is the thing to look at.

### The question in the title is still open

The routing was not changed. `ancestors ZZ` is unchanged:

```m2
i2 : ancestors ZZ

o2 = {ZZ, Number, Thing}
```

So `RingElement` still is not an ancestor of `ZZ`, and `quotient(Ideal, RingElement)` still does not
catch integers — a parallel `Number` method was added instead. That answers the symptom without
answering *"Is this on purpose?"*, which is what you actually asked.

If that question is worth keeping alive, [#1477](https://github.com/Macaulay2/M2/issues/1477) is
the better home: it is your same question about the dispatch of `lift` and `promote`, and it is
still open.
