Closing: this is fixed on the default path — but the old answer is still reachable, so it is worth
saying which is which.

On 1.26.06, `Ext^1(S^1/ideal(X*T-1), S^1)` returns `cokernel | XT-1 |`, agreeing with the
`res` → `Hom` → `HH^1` route you did by hand. Load the old implementation and the `0` comes back:

```m2
i1 : needsPackage "OldChainComplexes";

i4 : Ext^1(M, S^1)

o4 = 0

o4 : S-module
```

So the correct computation is the one in `Complexes`, written by @mikestillman in 2020 and now at
`Complexes/ChainComplex.m2:1182`, and what changed is which implementation runs. @mahrud's
[PR #3774](https://github.com/Macaulay2/M2/pull/3774) *"Complexes, OldChainComplexes, and
HomologicalAlgebraPackage"* (merged 2025-05-12) moved Core's `ChainComplex`-based `Ext` out to
`OldChainComplexes`, which made the `Complexes` one the default. Interestingly, what it does
internally is essentially your workaround — resolve, `Hom`, take cohomology.

**The caveat:** anyone who loads `OldChainComplexes` still gets `0` here. If that matters, it is a
separate issue from this one.
