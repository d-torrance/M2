Fixed in 1.25.11, and worth being explicit about which change did it, because neither pointer above
leads there.

`m2/set.m2` now has what this issue proposed:

```m2
set = method(TypicalValue => Set, Dispatch => Thing)
set Set         := identity
set HashTable   :=
set VisibleList := Set => set'
```

so `set set{1,2} === set{1,2}` is true. That came from `97fe4ce019`, "made set(Set) an idempotent", in
#3929 — which is also where `toList Tally` landed.

Correcting the record: #3574 is "leadTerm Ideal returning an Ideal" and did not make this change, and
#3770 was **closed without being merged**. So following the two references in this thread would
suggest the fix is still outstanding when it is not.

@DanGrayson's 2022 suggestion is what was eventually done — converting `set` from a compiled function
to a method function, the same way `toList` had just been converted.
