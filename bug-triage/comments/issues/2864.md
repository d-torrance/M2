Closing as a duplicate of #1881, which @mahrud identified above — but only the first half of this
issue is that duplicate, so the second half has been carried over there rather than closed with it.

**The first half is #1881 exactly.** *"`options dual` returns null"* is what @MichaelABurr raised in
January 2021, and it is still true on 1.26.06. #1881 is the older issue and the one with the
design discussion, including @DanGrayson's two alternatives.

**The second half is not in #1881 and is unmet** — and it fails silently rather than erroring.
Writing `dual MyType := F -> ...` without the `{} >> o ->` is accepted, and `F` then arrives as the
pair `(OptionTable{}, MyType{})`:

```m2
i3 : dual MyType := F -> class F

i4 : dual X

o4 = Sequence
```

The `{} >> o ->` form receives `MyType{}` as intended, and also correctly rejects an unknown
option, which the plain form swallows.

Worth knowing before anyone works on it: **the shortcut asked for already exists, for a different
dispatch mode, in the same file.** `SingleWithOptions` (`m2/methods.m2:141`) and the binary path
(`:103`) both short-circuit with `if #o === 0 then (f -> f arg)`, so a plain function does work
there:

```m2
i5 : f = method(Options => true, Dispatch => Thing);

i6 : f MyType := F -> class F

i7 : f X

o7 = MyType
```

`MultipleArgsWithOptions` (`:152-163`), which is what `dual` and every default-dispatch method with
options is, always calls `innerMethodFunction(o, arg)` instead.

That paragraph is now on #1881 as well, so nothing here is lost by closing this.
