Closing as fixed — this was done in 2018, reported here at the time, and just never closed.

@lilysilverstein's second comment on this thread,

> Rewrote this documentation to include things like Galois fields and rings declared as
> fields.

is `39cc70ff91` ("rewrite flattenRing and its options", 2018-07-22), carried by **#870**,
merged 2018-11-14.

### The specific complaint is gone

The headline that prompted the report is no longer there. `flattenRing-doc.m2:15` now reads

> write a ring as a (quotient of a) polynomial ring

with the "over ZZ or a prime field" clause dropped — which is the whole of what was
inaccurate.

All three cases named in the report are now documented with worked examples:

| named in the report | on the page today |
| --- | --- |
| Galois fields | *"`flattenRing` can also be used to represent GaloisFields as quotients of polynomial rings"*, with `K = GF(5^3)` |
| function fields | `K = frac(ZZ[a])`, then `B = K[x,y,z]/(...)`, showing the coefficient ring of the result is `K` |
| `toField` rings | *"Once a ring has been declared to be a field with `toField` then it will be used as the coefficient ring"*, with `A = QQ[a]/(a^2-3)` |

The page also now states the general rule the old headline was a special case of — *"By
default `flattenRing` attempts to define a new ring over either `ZZ` or a base field"* — and
the `Result` option, which @lilysilverstein said in the same comment she found confusing, was
rewritten with examples of each accepted form.

Thanks @kschwede for the report and @lilysilverstein for doing the work; the only thing left
undone was closing the issue.
