@mahrud's two questions have answers, and the second one explains the first.

**M2's tail-call optimization covers exactly one call shape**: a closure of *one* parameter, applied
to an argument that does not evaluate to a `Sequence`. That is the final `else` branch of `applyFCC`
(`d/evaluate.d:627`), whose `while true do (...)` loop at `:644` increments and decrements
`recursionDepth` around `evalAllButTail` and so leaves it **flat** across iterations. No stack
growth, so no limit, so `g 0` loops forever rather than erroring. Every other shape increments once
per call and trips at 300: a `sequenceCode` argument dispatches to `applyFCCS` (`:616`, `:821`) and a
`Sequence`-*valued* argument to `applyFCS` (`:626`, `:492`), and neither of those has the loop. That
covers `f()`, `h(0,0)` and `i(0,0,0)`.

**And that second dispatch is why `g()` differs from `g(0)`** — `g()` binds `x` to the empty
sequence:

```m2
i1 : g = x -> print class x;

i2 : g()
Sequence

i3 : g(0)
ZZ
```

So in `x -> g x` reached through `g()`, the recursive call is applying `g` to a `Sequence` value,
which takes the `applyFCS` path and loses the optimization. Confirmed by construction: a body of
`g (1:x)` hits the limit, bodies `g x`, `g(x)` and `(g x)` all loop, and `identity g x` hits the
limit because the recursive call is no longer in tail position.

So the reported behaviour is correct tail-call optimization rather than a missing guard — **but
there is a real defect here, and it is in the documentation.** The `recursionLimit` node
(`Macaulay2Doc/ov_debugging.m2:401`) says:

> Each time a function is called, the recursion depth is incremented by 1, and each time a function
> returns, the recursion depth is decremented. This limit on recursion depth is a way to detect
> infinite loops.

Both sentences are false for the optimized shape, and that text is exactly why this reads as a bug.
The `recursionDepth` node two blocks below already carries the sentence that belongs here — *"Tail
recursion optimization may be in effect, so there the answer may not always be what you expect."*
Nothing else in `Macaulay2Doc` mentions the optimization at all; `git grep` for "tail recursion" and
"tail call" over the documentation packages returns nothing.
