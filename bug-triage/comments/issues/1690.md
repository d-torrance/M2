Closing this: the example in the body works.
[`6114b0cfda`](https://github.com/Macaulay2/M2/commit/6114b0cfda), in
[#3686](https://github.com/Macaulay2/M2/pull/3686) (merged 2025-04-21, with documentation and
unit tests in the same PR), allows two or three input types to `new ... from`. The PR does not
reference this issue, which is why it stayed open.

On 1.26.06-40-gd8e86d689d:

```m2
i8 : new X from (Y, Z, W) := (T,a,b,c) -> new X from {"YZW"};

i9 : new X from (y, z, w)

o9 = X{YZW}

o9 : X

i10 : last methods NewFromMethod

o10 = (NewFromMethod, X, Y, Z, W)

o10 : Sequence
```

So the key is flat rather than `(NewFromMethod, X, (Y, Z, W))` — the "maybe the last items don't
need to be in a sequence" reading. A fourth input type is refused with
`expected 1 to 3 arguments`, since the output type counts as one of the four.

The follow-up above — `new (A, B, C) from (X, Y, Z)`, and the matching `installMethod` syntax —
is not covered by that, and it is tracked elsewhere: making `(X, Y, Z)` a legal type expression
is #1375, where @DanGrayson proposed exactly that reading on 2020-12-13, the day this issue was
filed; and reaching a constructor from its output types is #1331, where he showed
`select(pairs typicalValues, (k,v) -> v === Variety)` already does it for a single type. Both are
open, and `method(TypicalValue => (A, B))` still answers
`error: expected typical value (A,B) to be a type`.
