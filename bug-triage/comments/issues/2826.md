Still reproduces on 1.26.06-40-gd8e86d689d, and two things about it are not in the thread yet.

**The recursion is not in the determinant.** `precision A` for a `FreeAlgebra` loops forever
between `precision Ring := R -> precision 0_R` (`m2/reals.m2:29`) and
`precision RingElement := precision @@ ring` (`m2/enginering.m2:15`), because neither
`FreeAlgebra` nor `FreeAlgebraQuotient` installs a `precision` method of its own. `det` reaches it
before any algebra happens: `getMinorsStrategy` tests `precision R < infinity` first
(`m2/multilin.m2:31`). `minors(2, m)` hits the same loop.

**Name a strategy and it computes — and the two disagree.**

```m2
i4 : recursionLimit = 30

o4 = 30

i5 : precision A
stdio:5:9:(3):[1]: error: recursion limit of 30 exceeded

i6 : exteriorPower(2, m, Strategy => Cofactor)

o6 = | -cb+da |

             1      1
o6 : Matrix A  <-- A

i7 : exteriorPower(2, m, Strategy => Bareiss)

o7 = | ad-cb |

             1      1
o7 : Matrix A  <-- A
```

`da` and `ad` are different elements of `A`, so the answer you get depends on which algorithm the
strategy heuristic happens to pick. @mikestillman's question above already has an answer in the
source, in the body of `getMinorsStrategy` itself at `m2/multilin.m2:27-30`:

> Use the Bareiss algorithm unless R is a quotient of a polynomial ring. Note that if R is
> non-commutative then either algorithm is incorrect. What is the correct thing to do in this
> case?

So @moorewf's "just give an error" has a cheap second half that is worth doing whichever way the
first is settled: `precision` on a free algebra should terminate, since anything that consults it
— not only `det` — currently dies on a matrix over one.
