Closing this: @jchen419's explanation above is the whole of it, and the one part that looked like
a defect has since been fixed.

The two `(1-t)^-1` calls are not in the same ring. Before the assignment, `t` is still the
variable of `QQ[t]`, where `1-t` genuinely has no inverse:

```m2
i1 : QQ[t]/ideal(t^2);

i2 : class t

o2 = QQ[t]

o2 : PolynomialRing

i3 : (1-t)^-1
stdio:3:5:(3):[1]: error: element is not invertible in this ring

i4 : R = ooo;

i5 : class t

o5 = R

o5 : QuotientRing

i6 : (1-t)^-1

o6 = t + 1

o6 : R
```

That error message is the thing that has changed. In 2020 it read `division is not defined in this
ring`, which is what made the behaviour look bizarre — it is false of `QQ[t]`, where division is
perfectly well defined and this particular element simply is not a unit.
[`0e67628210`](https://github.com/Macaulay2/M2/commit/0e67628210), in
[#2480](https://github.com/Macaulay2/M2/pull/2480) (merged 2022-05-06), replaced it with `element
is not invertible in this ring`, which is accurate.

#1660, which this was split out of, is a separate matter and still reproduces.
