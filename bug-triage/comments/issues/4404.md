Both examples above are clean sequentially on 1.26.06-40-gd8e86d689d. The 10-variable one
(`ZZ/32003[s_0..s_9, Degrees => {6:1, 4:2}]`) gives 32 entries, all positive:

```
total: 1 35 160 340 303 173 118 35 1
```

and the 11-variable one with the degree-3 generator likewise has no negative entries.

**With threads, though, `minimalBetti` on that same ideal breaks here.** Scheduling eight
simultaneous calls at `allowableThreads = 13` did not complete a single round, failing two different
ways:

```
Complexes/FreeResolution.m2:91:17:(2):[10]: error: key not found in hash table:
        isComputable (of class Symbol)
```

```
-- SIGSEGV
-- SIGSEGV handler called a second time, aborting
```

The first is a torn read of a shared hash table, and that is the shape of failure that can yield a
Betti table with impossible entries — a partially-updated table read by another thread does not have
to fail loudly. The second matches the crash signature in
[#4226](https://github.com/Macaulay2/M2/issues/4226), which is also an engine computation under
`schedule`.

To be clear about what that does and does not show: no negative entries appeared in any of these
runs, so this is not the reported symptom reproduced. What it does establish is that concurrent
access to the resolution machinery corrupts shared state on an ordinary x86-64 machine, without any
help from non-standard degrees — which is a cheaper thing to chase than an HPC-only instability.
