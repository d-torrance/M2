Closing as obsolete: Debian no longer has a mips64el release architecture, so this build can no
longer occur.

Checked against the archive rather than inferred from Macaulay2 alone. `macaulay2` was built for
mips64el in oldstable (1.21+ds-3+b1) and for no suite since; stable, testing and unstable ship
`amd64 arm64 armel armhf i386 loong64 ppc64el riscv64 s390x` between them, with no mips64el.

That on its own would be ambiguous — a package can vanish from an architecture because it fails to
build there, which is what this issue reports. So the control is `bash`, which builds everywhere it
possibly can:

| suite | `bash` architectures |
| --- | --- |
| oldstable | amd64 arm64 armel armhf i386 **mips64el** mipsel ppc64el s390x |
| stable | amd64 arm64 armel armhf i386 ppc64el riscv64 s390x |
| testing | amd64 arm64 armhf i386 loong64 ppc64el riscv64 s390x |

mips64el is gone from `bash` too, so the architecture was retired rather than Macaulay2 dropping
off it.

If mips64el ever returns, or if the same failure shows up on another big-endian or memory-limited
architecture, this is worth reopening — the underlying `TateOnProducts` example may still be
fragile in ways that only an unusual platform exposes.
