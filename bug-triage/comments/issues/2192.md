Closing as a duplicate of #567, which is four years older and states the same missing implementation
more completely — it covers `lift` as well as `promote`, where this issue's title covers only
promotion. @mahrud linked the two here in 2023.

Since #567 has no comments of its own, the substance from this thread, so that it is legible from
there:

- `promote` on a `MutableMatrix` raises `MutableMatrix promote not implemented yet`
  (`m2/enginering.m2:129`), and `lift` raises `cannot lift given matrix` (`:138`). The second message
  is misleading — it reads as a claim that the lift is impossible, when `lift(matrix M, ZZ)` on the
  immutable copy of the same matrix succeeds. Whatever implements one should implement the other, and
  the `lift` message wants rewording regardless.
- Workaround, for anyone arriving from a search: round-trip through the immutable type,
  `mutableMatrix promote(matrix M, kk)` and `mutableMatrix lift(matrix M1, ZZ)`. Only useful when
  materialising an immutable copy is acceptable, which is not the case that motivates mutable
  matrices in the first place.

Worth noting how the three issues on this fit together, since #491 is closed and might mislead.
#491 reported `promote` and `lift` *silently returning zero matrices*; @mikestillman's answer there
was "I'll make it an error to call these functions, so it won't give the wrong answer", and it was
closed once that was done. So the wrong-answer bug really is fixed — what remains, and what #567
tracks, is that the functions were never implemented.
