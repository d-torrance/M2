@pzinn — the pattern is **any input line after the first one in a pasted block**, which on
Macaulay2Web is most of them, since input arrives a block at a time. That is also why this needs the
two lines entered together.

It is not the positions. `locate` is right in every case:

```m2
i1 : peek locate(() -> return)

o1 = FilePosition{stdio, 1, 12, 1, 25, 1, 12}

i2 : peek locate(() -> return)

o2 = FilePosition{stdio, 2, 12, 2, 25, 2, 12}
```

It is the input history. When several lines arrive at one prompt, the whole block goes into history
entry 1 and the following entries are empty:

```m2
i3 : apply(1..4, i -> getHistory(i + historyOffset))

o3 = (debug Core                                     , , , )
      historyOffset
      apply(1..4, i -> getHistory(i + historyOffset))
      code(() -> return)
```

One entry holding four lines, then three empty strings. `code` reconstructs stdio source by stacking
`getHistory` over the line range in the `FilePosition` (`m2/code.m2`, the `filename === "stdio"`
branch), so for a function defined on line 2 it stacks `""`, and then

```m2
if #file < stop then error("line number ", toString stop, " not found in file ", filename);
```

fires with `0 < 1`.

So #4351 is the trigger rather than the cause: it gave `return` a position, so `code` now attempts a
lookup it used to skip. The history-indexing gap is older and independent of it, and anything else
that reaches this branch for a non-first line of a block will hit the same error.
