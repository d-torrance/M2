Still reproduces on 1.26.06, and #944 turns out to be the same defect through a different
operator, so it is a duplicate of this issue and the two are being tracked here together.

`new MutableMatrix from M` aliases exactly as `copy M` does:

```
M = mutableMatrix{{1,2},{3,4}}
N = new MutableMatrix from M
N_(0,0) = 55

  M_(0,0)   is now 55
```

@DanGrayson's diagnosis above covers both — the hash table holds a pointer to the
`RawMutableMatrix` and it is the contents of that which get modified — but there is one thing
specific to `new … from` worth recording here: there is no `NewFromMethod` for
`(MutableMatrix, MutableMatrix)` at all. `lookup(NewFromMethod, MutableMatrix, MutableMatrix)` is
`null`, whereas `new MutableMatrix from Matrix` does exist, at `mutablemat.m2:34`, and copies
properly by going through `rawMutableMatrix raw m`.

So whatever is decided here should cover both entry points: `copy` needs to duplicate or refuse,
and `new … from` needs a method that does the same. The workaround in this thread,
`mutableMatrix matrix A`, still deep-copies and still works for either.
