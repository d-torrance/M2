Closing this: fixed, and by your own diagnosis, generalised.

[`396a1b419d`](https://github.com/Macaulay2/M2/commit/396a1b419d) — @kellerlv, in
[#4410](https://github.com/Macaulay2/M2/pull/4410), merged 2026-06-05 — removed the
`isHomogeneous` split in `adjoinVariables` entirely. The `else` branch you quoted,

```m2
newCycleDegrees = apply(cycleList, z -> {first degree z + 1})
```

is now

```m2
newCycleDegrees = apply(cycleList, z -> normalizeLen(degree z + tempDegree))
```

where `normalizeLen` pads *or* truncates to the length of `A.Degrees`. You proposed
`{first degree z + 1, 0}`, which is the same fix with the target length hardcoded to 2; item 4 of
the commit message describes this failure directly.

It is worth saying that the fix is genuinely recent, and not a side effect of the DGAlgebras 2.0
overhaul that came a month earlier: at `be67bb9b1a` (#4199, merged 2026-04-28) the `else` branch
is still there verbatim.

Running your example on 1.26.06-40-gd8e86d689d, `acyclicClosure A` returns the DG algebra with no
error. One note for anyone re-running it: the constructor is `freeDGAlgebra`, singular — there has
never been a `freeDGAlgebras`, so the snippet as written fails on the name before it gets as far
as the bug.
