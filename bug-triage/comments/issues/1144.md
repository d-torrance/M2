Still true, and re-measured on a tree that does not already deduplicate.

The `/usr/share/doc/Macaulay2` on a Debian or Ubuntu **package** install is not a valid place to
check this, because that packaging runs `jdupes` itself — measuring it measures the fix. So this is
the `.deb` from the cmake CI build instead
([run 32095406056](https://github.com/Macaulay2/M2/actions/runs/32095406056), checksum verified,
20,067 files, no hard links):

```
$ jdupes -rm usr/share/doc/Macaulay2
71 duplicate files (in 65 sets), occupying 1 MB
```

**1,985,143 bytes reclaimable** — about double the 2020 figure, on a documentation tree that has
grown by half.

### Every duplicate is example output

All 136 files are `.out` files under `example-output/`. Nothing else in the documentation tree
duplicates at all — no HTML, no images, no databases.

### And 95% of the bytes are two sets, both in SpectralSequences

| bytes | copies | files |
| ---: | ---: | --- |
| 637,956 | 3 | `pruningMaps.out`, `pruningMaps(SpectralSequencePage).out`, `PageMap.out` |
| 610,049 | 2 | `spectralSequencePage(FilteredComplex,ZZ).out`, `SpectralSequence ^ ZZ.out` |

Those two account for 1,885,961 of the 1,985,143 bytes. **The remaining 63 sets come to about
99 KB between them**, and 42 of those are under 1 KB — the median duplicate is 531 bytes, and the
smallest is 69.

That changes the shape of the question in the opening comment. Adding `jdupes` (or `fdupes`, or
`dupmerge`) as a build dependency to reclaim 1.9 MB is a fair amount of machinery for what is
mostly two documentation nodes: `SpectralSequences` emits 600 KB of example output apiece for
`pruningMaps` and `spectralSequencePage`, and sibling nodes repeat it verbatim. Trimming those two
examples would recover 95% of the total with no new dependency and no build step.

It also supports @mahrud's point above. If example output lived only in the database files and
`.out` files were not distributed, this class of duplication would not arise at all — and since
every duplicate here is an `.out` file, that single change would take the count to zero rather than
to 5%.
