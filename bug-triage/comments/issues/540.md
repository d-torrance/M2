Still exactly as reported, ten years on. On 1.26.06 `QQ[x,x_1]` emits the same warning twice, with
the same `debug 9868`, and Dan's two asks from this thread are both still open — rewriting the scan in
`enginering.m2` as `R.generatorSymbols <- R.generators` so that `<-` can detect it, and working out
why it prints twice.

This is now the surviving issue for #2771, which reported the same warning in 2023 and which I have
closed as a duplicate. Carrying over the parts of that thread this one did not have:

- It also happens across two rings sharing letters, which is how most people meet it:
  `QQ[a,b,c]` then `QQ[a_1..c_3]` warns for all three symbols. Verified on 1.26.06.
- The warnings come back on `use S`, not only when the ring is created.
- @mahrud asked for more than a better message: "It would be great if even `QQ[a,a_1,a_2]` worked
  fine." It still warns twice for `a`.
- @DanGrayson gave the reason it is not easy, which is the only design content on either issue:
  "Where would you store the values for `a_1, a_2`, etc.? Currently they're stored in `a`. We could
  store them in a global table instead of in `a`. I wonder how that would affect garbage collection."
- @pzinn asked what the "debug with expression" hint means, and Dan explained: evaluating it makes the
  next clearing of that variable drop you into the debugger instead.
