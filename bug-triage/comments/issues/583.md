Both parts still apply. The message is unchanged:

```
M2/Macaulay2/d/tokens.d:50:  export throwMessage := "unhandled throw command";
```

and `git log -S` puts its last edit in 2008, so it predates this issue by nine years and has

The main argument against doing it is that `throw` and `catch` are documented *together* —
`Key => {"throw", "catch"}` at
[`Macaulay2Doc/ov_language.m2:586`](https://github.com/Macaulay2/M2/blob/development/M2/Macaulay2/packages/Macaulay2Doc/ov_language.m2#L586) —
so a reader looking up `throw` cannot avoid seeing `catch` on the same page. The message
would be pointing at documentation the user has already been handed.

### Recorded in case anyone ever wants it

Both halves are small, and the second is smaller than it sounds. The thrown value is already
carried on the error object, so displaying it needs no new plumbing —
[`d/evaluate.d`](https://github.com/Macaulay2/M2/blob/development/M2/Macaulay2/d/evaluate.d):

```
:1864   when e is Error do e else Expr(Error(dummyPosition,throwMessage,e,false,dummyFrame))
:1709   when p is err:Error do if err.message == throwMessage then err.value else p
```

Line 1864 is `throw` putting the value into the error's `value` field; line 1709 is `catch`
reading it back. Wherever the unhandled-throw message is printed, `err.value` is in hand.

So if this is ever revisited, it is a one-line change at `tokens.d:50` and a small one
alongside it. It is being closed because it is cosmetic and the documentation already
covers the confusion, not because it would be difficult.
