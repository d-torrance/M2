Still the case on 1.26.06, and closing as a duplicate of #364 (`copy MutableMatrix`, 2016), which
is the same defect reached through a different operator.

`new MutableMatrix from M` does not copy — the result shares the original's contents:

```
M = mutableMatrix{{1,2},{3,4}}
N = new MutableMatrix from M
N_(0,0) = 55

  M_(0,0)   is now 55
```

`copy M` behaves identically, which is what #364 reports. @DanGrayson's diagnosis there is the
explanation for both: a mutable matrix is a hash table one of whose entries is a pointer to the
`RawMutableMatrix`, and it is the contents of *that* which get modified, so duplicating the table
does not duplicate the matrix.

What is specific to this issue is that there is no `NewFromMethod` for
`(MutableMatrix, MutableMatrix)` at all — `lookup(NewFromMethod, MutableMatrix, MutableMatrix)` is
`null` — whereas `new MutableMatrix from Matrix` does exist, at `mutablemat.m2:34`, and copies
properly by going through `rawMutableMatrix raw m`. So the expectation in this issue is right, and
the same fix that gives `copy` a sensible answer for mutable matrices should give `new … from` one.

The workaround from #364's thread applies here too: `mutableMatrix matrix M` deep-copies, and
editing the result leaves the original alone.
