Carrying over a second ask from #2864, which is being closed as a duplicate of this issue: the
`options`-returns-null half of it is this issue, but @mikestillman raised something there that is
not recorded here.

> Similarly, if we write a version of dual without optional arguments, currently we need to write
> something like `dual MyType := {} >> o -> F -> (....)`. However, since the code can know that
> `dual` takes options, if none are given, perhaps the user shouldn't need to write the
> `{} >> o ->` part?

Still true on 1.26.06, and the failure is silent. Omitting the boilerplate is accepted, and the
function then receives the pair `(OptionTable{}, MyType{})` rather than the object:

```m2
i3 : dual MyType := F -> class F

i4 : dual X

o4 = Sequence
```

It also swallows unknown options, where the `{} >> o ->` form rejects them.

The useful part for whoever takes it on: **the shortcut already exists for a different dispatch
mode, ten lines away.** `SingleWithOptions` (`m2/methods.m2:141`) and the binary path (`:103`) both
short-circuit with `if #o === 0 then (f -> f arg)`, so a plain function works there —

```m2
i5 : f = method(Options => true, Dispatch => Thing);

i6 : f MyType := F -> class F

i7 : f X

o7 = MyType
```

— while `MultipleArgsWithOptions` (`:152-163`), which is what `dual` and every default-dispatch
method with options is, always calls `innerMethodFunction(o, arg)`.
