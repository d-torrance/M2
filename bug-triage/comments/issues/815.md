Two things worth recording here: the scope is wider than the title suggests, and the reproducer
in this issue no longer demonstrates it — so a clean render is not evidence that it is fixed.

### It is not specific to `input`

`separateM2output` splits captured example output on `M2outputRE`, which is unchanged apart from
being rewritten as a lookahead (`M2/Macaulay2/m2/examples.m2:20`):

```m2
M2outputRE = "\n+(?=i+[1-9][0-9]* : )"
```

Feeding it three transcripts directly:

| given to `separateM2output` | chunks | |
| --- | ---: | --- |
| two genuine examples, `i1 : 1+1` and `i2 : 2+2` | 2 | correct |
| **one** example, `i1 : print "i5 : fake"`, whose output is `i5 : fake` | 2 | the printed text becomes a second example's input |
| **one** example that enters the debugger, with `ii2 :` prompts | 2 | the debugger interaction becomes a second example |

So anything whose *output* looks like a prompt is split there — a bare `print` will do it, and so
will any example that drops into the debugger. `input` is the common way to hit it rather than
the cause, which is what @DanGrayson's *"no way to distinguish lines coming from `input` and
lines coming from an interaction with the debugger"* says; the `i+` in the pattern is there
precisely because it is trying to match `ii` debugger prompts as well.

### The example that showed this was removed, not fixed

`72b5cd6db5` (2021-10-11) took the `input` example out of "reading files" and left the reason in
the source, at `Macaulay2Doc/ov_files.m2:157`:

```m2
	  -- we don't illustrate the use of 'input' here, because the documentation example parser can't handle it
```

The node now says "One may use `input` for that" with no example, and its numbering runs `i10`
straight to `i11`. So running the transcript from this issue today produces correct output. That
is the withdrawal of the trigger, not a fix.

### On whether it is decidable

It is worth saying that the information is discarded rather than absent.
`captureExampleOutput(desc, inputs, pkg, inf, outf, ...)` has the list of example inputs in hand
and writes the `.out` file keyed by `inputhash`, but `separateM2output` receives only the output
string. Two routes follow from that: align the stream against the known inputs, so that a prompt
not followed by the next expected input is output rather than input; or emit a delimiter at
capture time, which the `-- -*- M2-comint -*-` format can absorb since it is M2's own and
hash-keyed, so stale caches regenerate rather than break.

Neither is free, and the affected examples are rare and avoidable — one has already been
avoided. Recording the options here rather than arguing for them.
