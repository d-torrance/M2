Closing as a duplicate of #540, which reported the same thing in 2016: `QQ[x,x_1]` emitting the
`clearing value of symbol x` warning, and the same objection — that it reads like a bug report when
nothing is wrong. Diane put it as wanting it to "look less like it's a bug"; the wording here is that
it "makes it seem to the user that there is a problem".

Everything above still reproduces on 1.26.06, including the debug numbers unchanged from the
transcript: `QQ[a,b,c]` then `QQ[a_1..c_3]` warns for all three symbols with `debug 9539`, `9042` and
`8545`, and `use S` warns again. @mahrud's `QQ[a,a_1,a_2]` still warns twice for `a`.

I have carried the parts of this thread that #540 did not have over there, so nothing is lost by
closing this one: the two-rings-sharing-letters shape, the repetition on `use`, the stronger ask that
`QQ[a,a_1,a_2]` simply work, and @DanGrayson's explanation that `a_1` and `a_2` values are stored in
`a` so `a` cannot hold both, with a global table as the alternative and its effect on garbage
collection unknown. That last point is the only design answer either issue has, and it is worth
following on #540.
