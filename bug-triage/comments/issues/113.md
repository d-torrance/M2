Status note from a sweep of the open issues. **Partly addressed, and left open**, because
the two things this issue actually asked for are untouched. Rechecked on 1.26.06-40.

### What changed

The wrong *answers* are gone. `sub(m, matrix{{1}})` no longer returns something incorrect
— it raises instead, from
[`m2/ringmap.m2:187`](https://github.com/Macaulay2/M2/blob/development/M2/Macaulay2/m2/ringmap.m2#L187):

```
i2 : m = matrix{{1/2 * x}}

o2 = | 1/2x |

i3 : sub(m, {x=>1_ZZ})

o3 = | 1/2 |

i4 : sub(m, matrix{{1}})
stdio:4:3:(3):[1]: error: cannot map rational to this ring
```

The `CC_53` half behaves the same way: `sub(matrix{{ii*z}}, matrix{{1}})` raises rather
than crashing or returning `0`, which is what the report described in 1.6 and in the
linalg branch.

### What did not change

Both of the "should give an error" asks still construct without complaint:

```
i5 : f = map(ZZ, R, {1})

o5 = map (ZZ, R, {1})

o5 : RingMap ZZ <-- R
```

and likewise `map(RR_53, S, {1})` for `S = CC[z]`. The body asked for
"REALLY: should give an error: cannot construct ring map from R --> ZZ", and that is
where the issue put the real fix — *"if `f` cannot be constructed, this will not be a
problem"*. The map is still constructible, so the problem is still there; what has
happened is that the failure moved from the point of use to a different point of use.

And the remaining `sub` behaviour is not what was requested either. The report asked that
`sub(m, matrix{{1}})` give the same answer as the line above it, `matrix{{1/2}}`. It gives
an error. That is better than a wrong answer and it is not the requested behaviour.

The two cases the report singled out as already correct are still correct:
`sub(m, {x=>1_ZZ})` and `g m` for `g = map(QQ[y], R, {1})` both give `| 1/2 |`.

### Summary

| the report asked | today |
| --- | --- |
| `sub(m, {x=>1_ZZ})` correct | unchanged, correct |
| `sub(m, matrix{{1}})` should give `matrix{{1/2}}` | errors instead of returning a wrong value |
| `map(ZZ, R, {1})` should be refused | still constructs |
| `f m` wrong | moot while `f` is constructible |
| `g m` correct | unchanged, correct |
| `map(RR_53, S, {1})` should be refused | still constructs |

Recording this so the next person to look does not have to re-derive which half moved.
