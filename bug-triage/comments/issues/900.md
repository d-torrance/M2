Closing this — `make install` with `DESTDIR` works on the mainstream path now, and the evidence is
a package built exactly that way.

The Debian and Ubuntu packages are built through debhelper, which injects `DESTDIR` into
`make install`, with `--prefix=/usr`. Checking the resulting installation: every file lands under
`/usr`, and the build path does not appear in the installed documentation —

```
"configure arguments" =>  '--build=x86_64-linux-gnu' '--prefix=/usr'
                          '--includedir=${prefix}/include' ...
```

That is the scenario reported here — `--prefix` set to the real destination, `DESTDIR` set to a
staging directory — and it produces no stray files.

### One correction to the thread, since it explains the second half

@DanGrayson's suggested work-around above was to put the staging directory into `--prefix`
instead of using `DESTDIR`, on the grounds that *"there are no hard-wired paths in the files we
build, so it ought to just work."* That is what produced the leakage @kmarius reported
immediately afterwards:

> `usr/share/doc/Macaulay2/Macaulay2Doc/html/_version.html: configure arguments => ... '--prefix=/build/macaulay2-git/pkg/macaulay2-git/usr'`

`version#"configure arguments"` is recorded verbatim into the installed documentation, so putting
a staging path in `--prefix` necessarily bakes it into the installed files. The work-around was
therefore never equivalent to `DESTDIR`, which is precisely why `DESTDIR` is the right mechanism:
with it, the recorded prefix is the final `/usr` and nothing leaks.

### What this does not cover

@kmarius was on Arch with `--enable-download` and `--enable-shared`, and that exact combination
has not been retested here. If stray files outside the staging directory still appear with those
options, please reopen with the `make install` log — the mechanism would be a path that escapes
`$(DESTDIR)` in `M2/distributions/install/Makefile.in`, which is where the seven current uses of
it live.
