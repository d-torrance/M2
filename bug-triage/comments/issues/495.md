Closing as fixed — this was resolved the day after it was filed, and never closed.

[`76dffc03f4`](https://github.com/Macaulay2/M2/commit/76dffc03f4) (2016-07-09,
*"instead of looking in lib64, clear CONFIG_SITE for our libraries"*) answered both
questions asked here by removing the need for either. Rather than concentrating the `lib64`
searches or switching them to `@libdir@`, it stops the redirection happening at all:

```make
# clear this environment variable so the ambient system doesn't offer advice to
# our libraries that use autoconf about where to install install things.  The
# first example we encountered is under opensuse leap 42.1, which sets the
# autoconf variable libdir to ${exec_prefix}/lib64 instead of
# ${exec_prefix}/lib.  Our libraries' files are installed in only our private
# directories, so it's safe to ignore such system conventions.
export CONFIG_SITE =
```

— `M2/include/config.Makefile.in`, which is the file this issue proposed concentrating the
code in.

That commit deleted thirteen hardcoded `lib64` fallbacks across six files:
`Macaulay2/bin/Makefile.in`, `Macaulay2/m2/Makefile.in`, `check-configure/Makefile.in`,
`include/config.Makefile.in`, `libraries/Makefile.in` and `libraries/Makefile.library.in` —
lines like

```make
-# the use of */lib64 below is a kludge
-	LD_LIBRARY_PATH="$(BUILTLIBPATH)/lib64:$(BUILTLIBPATH)/lib:$$LD_LIBRARY_PATH" ...
-	-L$(BUILTLIBPATH)/lib64
-	PKG_CONFIG_PATH=$(BUILTLIBPATH)/lib64/pkgconfig:$(BUILTLIBPATH)/lib/pkgconfig:...
```

The reasoning holds up: the distribution's convention is about `/usr`, where 32- and 64-bit
libraries have to coexist. M2's private staging directory has no such constraint, so there
is nothing there for `libdir=lib64` to accomplish.

Three `lib64` mentions survive in the build system and all three are legitimate:
`configure.ac:948,951` searches `/usr/lib/4ti2/bin` and `/usr/lib64/4ti2/bin` for a
*system-installed* 4ti2, which really does live in `lib64` on Fedora; `config.Makefile.in:20`
is the comment above; and `m4/ax_boost_base.m4` is a vendored third-party macro looking for
system Boost.
