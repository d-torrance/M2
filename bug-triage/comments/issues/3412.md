This is the expected behaviour rather than a bug, and the clearest way to see it is without `value`
at all:

```m2
x = new HashTable from {};
```

`x` is the hash table. The semicolon suppresses *printing*; it never discards a value. `value` of a
string ending in `;` follows the same rule.

The mechanism confirms that, and answers the question this thread stopped on — @pzinn was right that
`returnLastvalue` is the relevant flag. `value String` calls

```
readeval(stringTokenFile("currentString", s.v+newline), true, true)
```

at `d/interp.dd:533`, with `returnLastvalue = true`, and `readeval4` at `d/interp.dd:120` returns
`if returnLastvalue then lastvalue else nullE` on reaching the EOF token. So `expr;` is a statement
list whose last statement is `expr`, and its value is that of `expr`.

That also accounts for the parenthesized case, which is a genuinely different construct rather than
an inconsistency: in `(expr;)` the trailing semicolon sits inside an expression sequence with an
empty final element, which does evaluate to `null` — so `value` sees `null` as the last value. Both
results follow from the grammar.
