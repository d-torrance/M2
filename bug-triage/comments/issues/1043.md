This works now, and gives the right answer.

```m2
i1 : needsPackage "PHCpack";

i2 : R = CC[x,y,z];

i3 : L = { z*(x+y), z*(x-y) };

i4 : W = cascade(L)

o4 : NumericalVariety
```

`W` has a dimension-2 component of degree 1 and a dimension-1 component of degree 1 — the plane
`z = 0` and the line `x = y = 0`, which is what `L` cuts out.

Tested against `phc` **PHCv2.4.90** (released 2024-03-20). Worth recording, since it bears on
[#1359](https://github.com/Macaulay2/M2/issues/1359): I could not attribute the change to anything
on the Macaulay2 side. `cascade` in `PHCpack.m2` has not been modified since `41b764a4f6` (2016),
and the error message above still exists, at `NAGtypes/Point.m2:44` — nothing that raises it was
touched. So the difference is most likely in `phc` itself, between whatever version was installed in
November 2019 and the current one.

If it reappears, the `phc` version is the first thing worth recording.
