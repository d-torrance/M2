Closing: this was fixed by #4249, *"Add minimalPrimes strategy for ideals in ZZ and ZZ/n"* (merged
2026-05-07), whose description opens "This closes #3505" and whose commit `79cd5b0292` added a
`MinimalPrimes/tests.m2` block headed `-- issue #3505`, covering `ZZ/5`, `ZZ/6` and a tower
`ZZ[][][][]/6`. The issue itself was never closed at the time.

Both reported errors are gone on 1.26.06, and the answers are the right ones — `ZZ/2` is a domain,
`ZZ/4` is not:

```m2
i1 : isPrime ideal 0_(ZZ/2)

o1 = true

i2 : isPrime ideal 0_(ZZ/4)

o2 = false
```

The *Related* question in the body — whether `frac` should check that its argument is an integral
domain — is **not** fixed, and is not being dropped with this close: it has its own issue in #4576,
which puts it more sharply than this one did. Over `ZZ[t]/(t^4)` the resulting fraction field's
multiplication is not associative, and the guard responsible (`m2/enginering.m2:335-343`) recurses to
the bottom of a tower of quotients without ever asking whether any of them is prime.
