Closing as obsolete. The architecture this was blocking is gone: asked in November 2021 whether it
was holding up releases, the answer here was "just on mipsel, which it's *never* successfully built
on", and mipsel is no longer a Debian architecture. No official Debian architecture is affected
today, and the non-official ones that currently fail to build do so for unrelated reasons.

Worth recording the cost before this closes, because nothing was actually fixed — `eigen.cpp` is
still a single file and the idea of splitting it was never taken up. Compiled standalone on amd64
with `g++ -O2 -DNDEBUG`, it peaks at **2.21 GB** and takes 67 s, against the 2.3 GB @antonleykin
measured in this thread in 2021. Same optimization level, so the footprint has not moved.

@antonleykin's per-routine breakdown from 2021-11-27 is the map for anyone who has to split it after
all:

| | RAM |
| --- | --- |
| all of `eigen.cpp` | 2.3 GB (~2.9 GB on Debian) |
| all SVD routines, RRR and CCC | 1.8 GB |
| divide-and-conquer SVD, CCC | 1.5 GB |
| divide-and-conquer SVD, RRR | 1.1 GB |
| SVD without divide-and-conquer | 0.9 GB |

with the caveat he added: compile times are not additive, so splitting function by function would
grow total build time, possibly by a factor of two.

Reopen if a constrained builder hits it again — the translation unit is unchanged, so the exposure
is too.
