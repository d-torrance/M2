Closing this as obsolete, but the cause is worth recording, because nobody on this thread found it
and the WSL explanation does not cover @martinkjlarsson's report from a fresh native Ubuntu 20.04.

It is [bdwgc#321](https://github.com/bdwgc/bdwgc/issues/321), filed six months before this issue.
Ubuntu 20.04 built its `libgc` package with `-Wl,-Bsymbolic-functions`, which leaves
`GC_data_start` resolving inside the executable while `data_end` resolves inside `libgc.so` — so the
pair really is inverted, and it happens on any Ubuntu 20.04 machine, WSL or not. Upstream fixed it
in `f9b288c` in August 2020. A commenter there notes in 2022 that it persisted in Ubuntu releases
"except Jammy", so 22.04 onward is clear.

Ubuntu 20.04 left standard support in May 2025, and Macaulay2 has built its own `libgc` for large
memory configurations since
[`122b8e3e3e`](https://github.com/Macaulay2/M2/commit/122b8e3e3e) (2022), so neither reporter's
configuration is reachable now. If anyone still hits this message on a current system, please open
a new issue — it would be a different bug.
