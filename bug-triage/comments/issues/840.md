Still open, and there is a worse case than the one in the report: the same clash with **no
assignment** is not an error at all, and silently breaks the imported package.

### Exporting without assigning is silent, and destroys the method

`Polyhedra` owns `ambDim`. A package that imports Polyhedra and exports that name, without ever
assigning to it, loads without a word:

```m2
newPackage("Clash2",
    PackageImports => { "Polyhedra" },
    DebuggingMode => true
    )
export "ambDim"
```

```m2
i1 : needsPackage "Polyhedra"; P = hypercube 2;

i3 : ambDim P

o3 = 2

i4 : loadPackage("Clash2", FileName => "Clash2.m2")     -- no warning of any kind

i5 : ambDim P
stdio:5:1:(3): error: no method found for applying ambDim to ...
```

Afterwards `package getGlobalSymbol "ambDim"` is `Clash2`, `Clash2.Dictionary` contains it, and
its value is the bare symbol `ambDim` — unassigned. So the export took ownership of the name and
left nothing behind it, and Polyhedra's method is unreachable. Nothing was printed at any point,
which is worth noting because M2 does emit `--warning: symbol ... is shadowed by ...` in other
circumstances.

That is the case an export-time warning would catch, and it is the one that costs something.

### The reported case is refused, and refused well

With the assignment present, the behaviour is correct and the message is better than it was in
2018 — it names the owner and where the symbol came from:

```
Clash.m2:8:15:(2):[10]: error: assignment to protected global variable 'ambDim',
    originally defined at .../Polyhedra/core/globalMethods.m2:6:0:(2)
```

So there is no argument for allowing the assignment; the ask is only about where the diagnostic
falls, and on that narrow point the current message is arguably good enough.

### The reproducer in the body no longer reproduces

`Polyhedra` no longer exports `intersection`, so the package above now loads cleanly and shows
nothing. Anyone re-checking this issue from the body alone would reasonably conclude it was
fixed. Substituting any symbol Polyhedra still owns — `ambDim` here — brings both behaviours
back.
