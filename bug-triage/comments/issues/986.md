### PR #4347 did the reorganization

[#4347](https://github.com/Macaulay2/M2/pull/4347), *"Organizing the e directory"*, by
@MichaelABurr, merged into `development` on 2026-06-06, carrying the file moves from the Atlanta
workshop. Measured against `e/` as it stood the day this issue was filed (commit `07422139`,
2019-08-10):

| | 2019-08-10 | today |
| --- | ---: | ---: |
| source files at the top level of `e/` | 315 | 77 |
| subdirectories of `e/` | 3 | 27 |

The three in 2019 were `doxygen-settings/`, `f4/` and `unit-tests/`. The list now covers nearly
every bullet in the body above: `rings/` and `basic-rings/`, `matrices/`, `mutable-matrices/` and
`basic-mutable-matrices/`, `interface/`, `monomials/`, `free-modules/`, `ring-elements/`,
`computations/`, `groebner-computations/`, `resolution/`, `resolutions/` and
`schreyer-resolutions/`.

The last question in the body — *"Remove all test code that is not part of M2, placing it in a new
directory?"* — is answered by `unit-tests/` and `unused/`.

### What is left is three specific things

- **No directory for utility code.** `buffer`, `comb`, `debug`, `mem`, `style`, `table`,
  `text-io`, `util`, `hash` and `exptable` are all still at the top level.
- **`ringmap.cpp` / `ringmap.hpp` are still at the top level**, against the *"ring maps"* bullet.
- **`hilb.cpp` is still at the top level**, against *"each computation type (GB, resolution,
  hilb)"* — `gauss.cpp`, `hermite.cpp` and `fractionfreeLU.cpp` are in the same position.

Those three are what a reader arriving at this issue now would want to know is outstanding,
rather than the whole survey.
