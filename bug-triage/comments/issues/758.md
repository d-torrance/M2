### Undocumented keys do get default pages

> Even better, all undocumented keys should have default html pages created for them, because
> there can be useful information on them that is automatically generated.

This happens now. Installing a throwaway package with one documented and one undocumented
exported symbol produces a page for each:

```
_doc__Fn.html   index.html   master.html   toc.html   _undoc__Fn.html
```

and `_undoc__Fn.html` carries exactly the automatically-generated content described:

```
TinyUndoc :: undocFn (missing documentation)

  undocFn

  For the programmer
    The object undocFn (missing documentation) is a function closure.
    The source of this document is in ...
```

### And the case that prompted the first half can no longer arise

The report begins from *"a new package had no top level documentation node, and it was referred
to in the file changes.m2, appearing in the html file as visibly undocumented."* A distributed
package can no longer be in that state: `M2/Macaulay2/tests/normal/release-checklist.m2`, added
by @d-torrance in `c1206e7146` (2024-05-10), fails the test suite if any package lacks one —

```m2
pkgs = select(pkglist, pkg -> (
	tag := makeDocumentTag(pkg|"::"|pkg);
	rawdoc := fetchRawDocumentation tag;
	rawdoc === null or rawdoc.Description === {}));
if #pkgs > 0 then error("packages with no top level node:", newline,
    toString stack sort pkgs)
```

and it runs as part of the normal tests, not only at release time.

### What survives, and why it is not this issue

One thing here is unchanged: `packages/Makefile.in:112-114` makes every package depend on
`Style`, `FirstPackage` and `Macaulay2Doc`, with no dependency in the other direction, so
nothing marks `Macaulay2Doc` for rebuild when another package's documentation changes. I have
not reproduced any current misbehaviour from that — it would need a full `make` — and the
symptom that was reported is now prevented upstream of it. If it turns out to bite in some other
form, that is worth its own issue with a fresh reproducer rather than reviving this one.
