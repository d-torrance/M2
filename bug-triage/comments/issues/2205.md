Two things worth recording rather than losing with the issue.

The test itself is fine elsewhere. The Debian package skips this test outright, so it does not run
even on amd64 — extracting the flagged block and running it directly on amd64 passes, including the
`assert(B1 == B2)` that failed here.

More importantly, **this was a wrong answer rather than a resource limit**, which sets it apart from
most of the architecture-specific build failures on this tracker. `minimalBetti` and `betti res`
disagreed on a 7-step nonminimal resolution over `ZZ/101` built via BGG. If the cause is
endian-sensitivity in the nonminimal resolution code rather than anything specific to MIPS, then it
would be expected to recur on s390x, which is also big-endian and is still built — and #2162 already
records F4 returning a *different basis* on s390x, which is the same class of symptom in adjacent
code.

So: closed because the platform is gone, not because the underlying question was answered.
