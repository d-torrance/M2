Carrying over one thing from #3242, which is being closed as a duplicate of this issue: a second
package reaches this same crash, by a much shorter route.

The stack there is the same two frames — `SLP<ComplexField>::concatenate` called from
`PathTracker::make`, at offsets shifted by exactly 11 from the ones in the report above — but it
arrives via `DecomposableSparseSystems::solveDecomposableSystem` rather than
`NumericalImplicitization::pseudoWitnessSet`, on a two-equation system in two variables
(`{3*x_2^3+x_1^2-1, 17*x_1-2*x_2+2}`, mixed volume 3) rather than a 3×5 generic matrix with
`Repeats => 2`. For anyone wanting to provoke this deliberately instead of waiting for it to turn up
in a build log, that is likely the cheaper starting point.

It also adds a data point on the frequency, which is the recurring difficulty with this issue: over
several days it fired repeatedly in one contributor's fork's GitHub Actions while the main
repository's runs were unaffected. That thread ended without an explanation for the asymmetry, and
the evidence gathered here — x86-64, s390x, armel and arm64 over four years, at a rate you described
as "very, very rare" — suggests there is nothing to explain beyond how often the code path gets run.
