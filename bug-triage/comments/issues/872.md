`adjugate` still does not exist anywhere in Macaulay2 — no method, no package, no other issue —
so this is unmet. Two things measured that bear on the question the thread stopped at.

### The relation to `exteriorPower` is exact

@DanGrayson's *"more than the signs differ"* is right, and the difference is signs **and** an
index reversal. Writing `E = exteriorPower(n-1, M)`, and taking the 180° rotation
`rev N = table(n, n, (i,j) -> N_(n-1-i, n-1-j))` and the checkerboard
`sgn N = table(n, n, (i,j) -> (-1)^(i+j) * N_(i,j))`:

```
adjugate M == sgn rev transpose E      -- true for n = 2, 3, 4
adjugate M ==     rev transpose E      -- false
```

So the two carry the same information and each is recoverable from the other by a fixed
reindexing. That is the fact bearing on *"we perhaps shouldn't have two such similar functions"*
— they are not merely similar, they are equivalent up to a permutation and a sign pattern, which
is an argument either for one of them or for defining `adjugate` in terms of `exteriorPower`
rather than in terms of `det submatrix'`.

### The proposed implementation is correct, but the degrees need a decision

The code in the report satisfies the defining identity:

```m2
i1 : R = ZZ[a..z]; M = genericMatrix(R, a, 3, 3); A = adjugate M;

i4 : entries(A*M) == entries(det(M) * id_(source M))

o4 = true
```

Note `entries`. As matrices the two are **not** equal, because their gradings differ — `A*M` has
source degrees `{3,3,3}` over target `{0,0,0}`, while `det(M) * id_(source M)` has `{1,1,1}` over
`{1,1,1}`. Nothing is wrong with either; `matrix table(...)` simply builds an ungraded result. But
an implementation that wants `adjugate M * M == det M * id` to hold as written, rather than only
on entries, has to construct the result with degrees rather than with a bare `matrix table`.

`return error "..."` is redundant — `if numcols M =!= numrows M then error "expected a square
matrix";` as a statement is the idiom.
