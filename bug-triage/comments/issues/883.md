### "block" is still undefined, and the node that would define it was never written

`Macaulay2Doc/functions/selectInSubring-doc.m2:15` still says

> consisting of those columns of `m` which lie in the subring where the first `i` blocks of the
> monomial order are zero

Line 17 glosses it once — *"the following block (or product) order"* — and three examples
illustrate it (`MonomialOrder=>{2,4,1}`, then `Lex` as a single block, then `{4:1}`), but nothing
says what a block *is*.

The reason is upstream of this function. `Macaulay2Doc/ov_monomial_orderings.m2` carries the list
of where each monomial order is defined, and in the middle of it:

```m2
     TO "GroupLex", ", ",
     TO "GroupRevLex", ", ",
     -- Mike wanted this: TO "product orders", ", ",
     TO "RevLex", ", and ",
     TO "NCLex", ".",
```

That commented-out line is older than the 2008 rename of the `Macaulay2` package to
`Macaulay2Doc`, so the "product orders" node was requested at least a decade before this issue
was filed and still does not exist. Every other order in that list has a node defining it; the
one that would define "block" is the gap.

So the documentation half of this issue is not really about `selectInSubring` — its doc is using
a term correctly, and the term has nowhere to point. Writing "product orders" and linking line 15
to it would settle it.

### The redesign is still open, and so is the question about it
