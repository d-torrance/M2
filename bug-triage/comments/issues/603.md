Closing as fixed — `M // N` over a finite field now behaves exactly as it does over ZZ and
QQ, which is what this issue asked for.

On 1.26.06-40, with `k = ZZ/32003`:

```
M = sub(matrix {{1},{0}}, k)      N = sub(matrix {{0},{1}}, k)

M // N                   map(k^1, k^1, 0)
M %  N                   | 1 |
                         | 0 |
N*(M//N) + (M%N) == M    true
```

and over `QQ`, where the issue reports it already worked, the answers are the same: quotient
`0`, remainder `M`, identity holds. `M` is not in the image of `N`, so a zero quotient with
everything in the remainder is the right result, and no error is raised in any of the three
rings.

### How it got fixed

@mahrud's diagnosis in this thread was exact:

> the code attempts to run and return `solve(M, N)`, which returns `null`, but when working
> with hooks `null` means the strategy "doesn't work", so the error is returned that no
> strategy is applicable. I imagine either `solve(M, N)` needs to return something other
> than `null`, or the code needs to be adjusted to check whether the result of `solve` is
> `null` and if so return zero(?)

The second option is what happened. `solve(N, M)` still returns `null` here — that has not
changed — but the quotient code no longer treats that as "no strategy applies". So the
parenthetical guess at the end of that comment turned out to be the fix.

### Worth knowing: the same `null` is still live elsewhere

`solve` returning `null` for an unsolvable system is the root of **#479** as well, where it
has *not* been handled. There, `solve` over `RR` returns `null` for an inconsistent system
and the caller produces the same
`no method found for applying matrix to: null (of class Nothing)` that this issue opened
with — and over `ZZ` it is worse, returning a matrix that does not solve the system at all.

So this issue is a worked example of the fix #479 still needs: check the `null` at the call
site and decide what it means, rather than letting it propagate as "no method". Anyone
picking up #479 should read @mahrud's comment above first.
