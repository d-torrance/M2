Closing as fixed — [`4612ae32d5`](https://github.com/Macaulay2/M2/commit/4612ae32d5) is
titled *"Address git issue #569: GB over local term orders now returns a minimal GB"* and
does what it says. Verified on 1.26.06-40 with @mikestillman's own assertions from the
comment above:

```m2
R = QQ{x,y,z}
i = ideal"xyz+z5,2x2+y3+z7,3z5+y5"
L = gens gb i
assert(numColumns L == 5)     -- passes
assert(gens gb L == L)        -- passes
```

The basis is minimal and stable under recomputation:

```
{2*x^2+y^3+z^7}, {x*y*z+z^5}, {y^4*z-2*x*z^5+y*z^8}, {y^5+3*z^5},
{3*z^6+2*x*y*z^5-y^2*z^8}
```

### On the caveat in the same comment

> However, reduction of elements is now sometimes slower (at least over QQ). This needs to
> be addressed, but in the next release.

That is still observable. The example given here, `L2_2 % i`, takes about 15 seconds.

**But that on its own is not evidence of a defect, and it is worth saying why**, because
the obvious check is misleading. Reducing the same element modulo the same generators under
a *global* order takes under a second, and it is tempting to read the gap as a regression.
It is not a fair comparison: a local order is not a well-ordering — `1 > x > x^2 > ...`
descends forever — so reduction under it has no descending-chain argument to terminate on,
and Mora's ecart restriction is what recovers termination. Slowness there is the expected
cost of that machinery rather than a symptom.

This exact territory was measured recently while triaging `bugs/mike/1-local-bug.m2` from
the pre-GitHub `bugs/` tree ([#36](https://github.com/Macaulay2/M2/issues/36)), and settled
as *not* a defect: `gbTrace = 15` on a slow local reduction showed 17,639 reduction steps
with every intermediate polynomial distinct — no cycle — the intermediate growing
monotonically from 7 terms to 1,160 to 4,019 to 6,951, and Mora's own termination measure
descending correctly throughout. Textbook intermediate expression swell, with the algorithm
making legal progress the whole way.

So the open question left by the caveat is narrower than "reduction is slow": it is whether
the *delta introduced by this fix* is a regression, or simply the cost of computing a
genuinely minimal basis where before an inflated one was returned. That cannot be settled by
comparing against a global order, and it has not been settled otherwise. If anyone wants to
pursue it, the comparison that would mean something is this same reduction before and after
`4612ae32d5`, not local against global.

Related and still open: #568, `mingens` in local rings, which @mikestillman noted here "is
more significant, and is perhaps really not a bug" — it still returns two generators where
one suffices. #293 remains the standing wishlist for standard bases over local rings.
