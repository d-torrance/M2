Closing this: @jkyang92's reply is the answer, and running it out confirms there is no induced map
here to produce.

`inducedMap` needs the two modules to sit in the same ambient free module, and that is exactly what
separates the two halves of the example. `truncate(3, M)` is a submodule of `M`, so both have
ambient `R^1`. `M ** I` is not — it comes back presented as a quotient, with ambient `R^9`:

```m2
i4 : ambient (M ** I), ambient M

       9   1
o4 = (R , R )
```

so the error message is reporting the situation accurately rather than declining a case it could
have handled.

The workaround does build a map, but not an injection:

```m2
i5 : f = M ** inducedMap(R^1, I);

i6 : kernel f == 0

o6 = false
```

Tensoring is not exact, so `M ** I -> M` has a kernel in general and there is no monomorphism for
`inducedMap` to return. That is the mathematics rather than a limitation of the implementation.

If what is wanted is something weaker — say `inducedMap` accepting a source in a different ambient
free module and composing with a canonical comparison map — that is a different request from the
one in the body, and worth its own issue, since it would not give an injection in this example
either.
