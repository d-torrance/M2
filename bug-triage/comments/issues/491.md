Closing as fixed, from a sweep of the open issues — the defect reported here is gone,
though it went the way this thread said it would rather than the way it hoped.

### The wrong answer is gone

```
i1 : kk = ZZ/101;

i2 : M = mutableMatrix(ZZ, 2, 2); M_(1,1) = 4;

i3 : promote(M, kk)
Core/enginering.m2:129:54:(1):[10]: error: MutableMatrix promote not implemented yet
```

and `promote(M,ZZ,kk)`, `lift(M1,ZZ)` and `lift(M1,kk,ZZ)` all raise the same way. No zero
matrices, because there is no answer at all.

That is exactly what @mikestillman said he was doing here in June 2016 — *"For now, I'll
make it an error to call these functions, so it won't give the wrong answer"*, then *"OK, I
made these functions give errors."* Silently returning zeros was the bug; refusing is not
that bug.

### What that leaves, and where it lives

The functions still are not implemented, which #567 already tracks — *"Lift and promote
with MutableMatrix not completely implemented"*, filed by @mahrud in January 2017. Its
reproducer still fails on 1.26.06-40, exactly as written:

```
lift(m, R)                         -- Matrix:         works, gives | x |
R_0 * m                            -- Matrix:         works, gives | x2 |
lift(n, R)                         -- MutableMatrix:  error
R_0 * n                            -- MutableMatrix:  error
mutableMatrix lift(matrix n, R)    -- workaround:     works
promote(R_0, K) * n                -- workaround:     works
```

So the same operations that work on a `Matrix` still refuse on a `MutableMatrix`, and
@mahrud's two workarounds both still do the job. #567 states that more precisely than this
issue does, and has a reproducer that fails rather than one that has been guarded.

The note about moving this to 2.0 has not been followed by a 2.0 milestone or by any work
in the decade since, and #567 says the same thing without the historical detour through
"returns zeros".

### The wider family, since these keep meeting each other

`lift`/`promote`/`MutableMatrix` accounts for a cluster in the tracker: besides #567, there
are #1477 (*Dispatching of lift and promote*), #2192 (*Promotion of mutable matrices*),
#2103, #3243 and #4376. They have not been read together and may not all be distinct; that
is worth someone's afternoon, but not a reason to keep this one open, since what it reported
no longer happens.
