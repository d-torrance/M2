This does what you suggested now — first `a` to first `a`, and so on.

```m2
i1 : R = QQ[a,a,a];  S = QQ[a,a,a];

i2 : f = map(R,S)

o2 = map (R, S, {a , a , a })
                  0   1   2

i3 : f(S_0), f(S_1), f(S_2)

o3 = (a , a , a )
       0   1   2

i4 : substitute(S_0*S_1, R)

o4 = a a
      0 1
```

The fix came from removing the ambiguity rather than from teaching `map` to resolve it. `QQ[a,a,a]`
no longer builds three identically-named generators; `dedupSymbols` (`m2/monoids.m2:473`) renames
them to `a_0, a_1, a_2`. @mahrud added that in `e1c2edb480` (2022-08-27) for the two-duplicate case,
and [#3262](https://github.com/Macaulay2/M2/pull/3262) *"De-duplicate three or more duplicate
variables"* (merged 2024-05-25) extended it to three or more, which is the case here.

Worth noting for anyone who lands on this later: the error above is still in the source, at
`m2/ringmap.m2:110`, unchanged since 2009. It has not been removed — it is simply no longer
reachable by writing repeated variable names, because there are no longer any repeated names to be
ambiguous about.
