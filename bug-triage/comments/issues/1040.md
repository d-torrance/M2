@antonleykin — answering your 2025 question. Closing as not reproducible, with the caveat below.

The distributed `Bertini` package does not permute solutions. Running the package's own test
example (`Bertini/TST/bertiniRefineSols.tst.m2`) against `bertini` on this machine:

```m2
i1 : needsPackage "Bertini";

i2 : R = CC[x,y];  F = {x^2-2, y^2-2};

i3 : W = bertiniZeroDimSolve F;   S = bertiniRefineSols(300, W);
```

Four solutions in, four out, in the same order position by position:

| | input | refined |
| --- | --- | --- |
| 0 | (1.414, 1.414) | (1.414, 1.414) |
| 1 | (1.414, -1.414) | (1.414, -1.414) |
| 2 | (-1.414, 1.414) | (-1.414, 1.414) |
| 3 | (-1.414, -1.414) | (-1.414, -1.414) |

**The caveat, and the reason this is "not reproducible" rather than "fixed":** this exercises the
distributed package, not the `IMA-Bertini` branch of @JoseMath's fork that the issue was filed
against, and no commit has been identified that changed the ordering behaviour. So it is an absence
of the symptom rather than a demonstrated repair.

If you still see the permutation, on that branch or elsewhere, please reopen — and @DanGrayson's
suggestion above still stands as the durable answer either way: having the calling code sort into a
canonical order would make it resistant to whatever `bertini` does with ordering in future.
