The reported symptom is gone, for two reasons.

**`usr-build` no longer exists.** It was removed in
[#3934](https://github.com/Macaulay2/M2/pull/3934), one of the items ticked off on
[#1091](https://github.com/Macaulay2/M2/issues/1091).

**And the search path was rebuilt.** `db6a2fb79e` (2021-06-29), *"Simplify construction of
pathsToTry list in findProgram"*, replaced the accumulated list with six explicit sources
(`m2/programs.m2:92-105`): `programPaths`, `prefixDirectory | currentLayout#"programs"`, the
caller's `AdditionalPaths`, `$PATH`, `bindir`, and `topBuilddir | "usr-host/bin"`.

### One duplicate does survive, and it is not the one reported

Measured on an installed M2 by looking for a program that does not exist: **19 paths searched, 17
distinct.**

- `/snap/bin` twice — but that is duplicated in the shell's own `$PATH`, so `findProgram` is
  faithfully reflecting its input.
- `/usr/bin/` twice — and this one is ours. `bindir` is `/usr/bin/` on this installation, and
  `/usr/bin` is also a `$PATH` entry, so the list contains it from two of the six sources.

That is one redundant `stat` per lookup rather than three, and on a directory that exists rather
than one that does not, so it is cosmetic. But it is the same shape as what this issue reported, and
it would be fixed by a `unique` on `pathsToTry`. Worth its own issue if anyone wants it; recording
it here so closing this one does not bury it.
