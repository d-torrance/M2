Closing as fixed. This was done ten months after it was filed, by `86edf9b2bc` (2019-11-26),
"configure script: find libxml2 better" — and never closed.

The block it added to `M2/configure.ac` opens by restating this issue's premise almost verbatim:

```
dnl        The installation of libxml2 under Mac OS X is problematic:
dnl            (1) Starting with Mac OS X 10.15, /usr/include is not present.  The compilers look in
dnl                /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/include instead.
```

and then does what was asked here, using exactly the proposed check:

```sh
if pkg-config --exists libxml-2.0
then XML_INCLUDE=`pkg-config --cflags-only-I libxml-2.0 | sed -e 's=^-I/=-isystem /=g' ...`
```

It goes further than the request in one respect. Rather than detecting the situation and
suggesting the fix documented in `INSTALL`, it repairs it: if `libxml/xmlexports.h` is not found,
it preprocesses `#include <libxml2/libxml/xmlexports.h>`, extracts the real directory from the
output, and prepends it to `CPPFLAGS`, so the build proceeds without the user doing anything.
`AC_CHECK_HEADERS(libxml/xmlexports.h libxml/parser.h)` afterwards names `libxml/parser.h`, the
header this issue asked about.

A case that cannot be repaired automatically is still reported —

```
AC_MSG_WARN([failed to extract path to libxml from preprocessor output:])
```

followed by the preprocessor output itself — so the diagnostic half of the request survives in
the only case where it is still needed.
