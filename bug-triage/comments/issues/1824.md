Closing this: the message is libgc's, and Macaulay2 is usually not the thing that built libgc, so
there is no text here for us to change. @DanGrayson's answer above — take it to
[the bdwgc tracker](https://github.com/bdwgc/bdwgc/issues) — is still the right route.

Worth recording why the "we are usually no longer building it" caveat in the original report has
not stopped being true, since it looks at first glance as though it has.
[`122b8e3e3e`](https://github.com/Macaulay2/M2/commit/122b8e3e3e) does configure our own gc for
larger heaps — `M2/libraries/gc/Makefile.in` passes `-DMAX_HEAP_SECTS=81920 -DMAXHINCR=4096` — but
that only applies when we build it:

- the CMake build never does by default: `build-libraries.cmake` adds the `bdwgc` target only
  `if(NOT BDWGC_FOUND)`, after `check-libraries.cmake` runs `find_package(BDWGC 7.6.4)`;
- the autotools build does by default, but `--with-system-gc` exists for packagers, and the
  distribution packages use it.

So on a typical installation the limits are whatever the distribution compiled, and so is the
message.

For anyone arriving here from that error: @mikestillman's own advice in
[GC garbage collector](https://macaulay2.com/doc/Macaulay2/share/doc/Macaulay2/Macaulay2Doc/html/___G__C_spgarbage_spcollector.html)
is the practical remedy — start Macaulay2 with a larger initial heap, e.g.
`GC_INITIAL_HEAP_SIZE=20G M2`.
