Closing this. Two of the three things asked for here have been settled — one by a change that
landed, one by a decision — and the third has an answer in a package that did not exist in 2019.

### `random QQ` is now uniform on the positive rationals of bounded height

`26f6707849`, in [#3798](https://github.com/Macaulay2/M2/pull/3798), re-rolls until numerator and
denominator are coprime. That is what removes the bias the body describes: before it, the pair
was drawn uniformly from `[1,h]²` and *then* canonicalized, so `1/2` arrived as any of `(1,2)`,
`(2,4)`, `(3,6)`, `(4,8)` or `(5,10)` while `7/9` arrived one way only.

20000 draws at the default `Height => 10` land on exactly the 63 coprime pairs in `[1,10]²`, from
`1/10` to `10`, with counts running 281 to 370 about a mean of 317 — uniform to within sampling
noise.

### Negatives would make `QQ` the odd one out

Every other `random` over a ring returns a non-negative value: `random ZZ` draws from `[0, Height)`
and `random RR` from `[0,1)`. Making `random QQ` signed on its own would be an inconsistency
rather than a fix, so this one is deliberate.

### For other distributions, use the `Probability` package

@kschwede asked in 2021 whether anyone was building a better distribution on the integers. The
[`Probability`](https://macaulay2.com/doc/Macaulay2/share/doc/Macaulay2/Probability/html/) package
ships with Macaulay2 now and covers this: fourteen named distributions, and
`discreteProbabilityDistribution` / `continuousProbabilityDistribution` for anything else,
including support that runs negative.

```m2
i1 : needsPackage "Probability";

i2 : X = discreteProbabilityDistribution(k -> if abs k <= 2 then 1/5 else 0, Support => (-2, 2));

i3 : apply(10, i -> random X)

o3 = {1, -1, -1, -1, -1, -1, -2, -1, -1, 1}
```

### One thing here is not settled by any of the above

The body's closing aside — that denominators are senseless when working in a polynomial ring over
`QQ` — still stands, and none of the reasoning above touches it:

```m2
i1 : R = QQ[x,y];

i2 : random(2, R)

      7  2   3        2
o2 = --x  + -x*y + 6y
     5      7
```

A random rational of bounded height has a denominator by construction, and `Height => 1` is not a
way out of it — it forces every coefficient to `1`. If integer coefficients over `QQ` are what is
wanted, that is a request about `random(ZZ, Ring)` rather than about the distribution on `QQ`, and
it would be better as its own issue than as a line at the end of this one.

### One piece of history, since this issue's timeline is misleading about it

[#3481](https://github.com/Macaulay2/M2/pull/3481) is cross-referenced above and merged, so it
reads like the fix. It was reverted by [#3798](https://github.com/Macaulay2/M2/pull/3798) 24 days
later — *"Revert random(QQ) changes (too slow)"* — after
[#3782](https://github.com/Macaulay2/M2/issues/3782). Its Farey-approximation code survives and is
what `random(x)` for `x : QQ` uses today (`m2/reals.m2:352`), which is a different method from
`random QQ` (`m2/rationals.m2:32`).
