Six of the thirteen requests on this thread are already implemented, so here is the state of each on
1.26.06 — measured, not read off the documentation.

From the original list:

- [x] **1.** `findProgram "normaliz"` with no test command — works.
- [x] **2.** `runProgram("normaliz", "--version")` with a string name — works.
- [x] **3.** `status runProgram(p, "--version")` — returns the code.
- [x] **4.** `toString runProgram(p, "--version")` — returns the output.
- [x] **5.** `p << input` — works, and does what @d-torrance proposed in this thread.
- [ ] **6.** `MinimumVersion` with a regex for extracting the version. Neither the
  `MinimumVersion => (min, cmd)` tuple nor the four-argument
  `findProgram(name, cmd, min, regex)` form parses.

From the 2024 additions:

- [ ] **1.** `findProgram` still requires the bare program to exit 0, so the `msolve` case stands.
  `findProgram "false"` raises while `findProgram "true"` succeeds; `cat` and `M2` pass only because
  they happen to exit 0.
- [ ] **2.** `p args` directly — raises.
- [ ] **3.** `p_args << stdinput` — raises.
- [ ] **4.** `RaiseError => false` with too high a minimum still returns `null` rather than a
  `Program`.
- [ ] **5.** `p.Version` raises, and there is no version key at all: a `Program` found without
  `MinimumVersion` has keys `{path, prefix, name}`.
- [ ] **6.** `runProgram` with a list or sequence of arguments — raises.
- [x] **7.** Live output. Done in bf9ac3eade, 2024-08-01, *"Print verbose runProgram output as it
  happens"* — the same day it was asked for here, which is presumably why nobody said so. Use
  `Verbose => true`; the commit message notes stdout may still not appear until the end if the
  program does not flush.

For reference, `options runProgram` is `{RaiseError, RunDirectory, KeepFiles, Verbose}`.
