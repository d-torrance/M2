Ten years and three distinct claims in this thread, so here is which of them are still true
on 1.26.06-40.

### The original report is fixed

@lkastner's example gives the right answer over ZZ now, without promoting to QQ:

```
i3 : solve(transpose im, transpose v)

o3 = | 1  |
     | -1 |
     | 1  |
     | -1 |
     | -1 |

              5       1
o3 : Matrix ZZ  <-- ZZ
```

That matches what the QQ round-trip produced then and now.

### @tom111's 2018 case is still live, and worse than "non-sensical results"

```
i4 : A = matrix {{0_ZZ,0},{0,1}}

o4 = | 0 0 |
     | 0 1 |

i5 : b = matrix {{1_ZZ},{1}}

o5 = | 1 |
     | 1 |

i6 : x = solve(A,b)

o6 = | 0 |
     | 1 |

i7 : A*x == b

o7 = false
```

The system is inconsistent — the first row asserts `0 = 1` — so there is no solution, and
`solve` returns a matrix that is not one. It does not warn, does not error, and does not
return `null`. A caller who does not check `A*x == b` gets a wrong answer silently, which is
a worse failure than the original report, where the answer was at least refused.

### @jchen419's 2019 point, from the other side

The same inconsistent system over `RR` returns nothing at all:

```
i8 : solve(matrix{{0.0,0.0},{0.0,1.0}}, matrix{{1.0},{1.0}})

i9 :
```

`null`, silently — which is what produces the downstream
`no method found for applying matrix to: null (of class Nothing)` reported above. So the two
rings disagree about how to fail: ZZ returns a wrong answer, RR returns `null`. Neither says
"this system has no solution", which is the information the caller actually needs and the
message @jchen419 asked for.

### Summary

| claim | status |
| --- | --- |
| `solve` over ZZ gives wrong/failed results on a solvable system (2016) | fixed |
| `solve` over ZZ returns a non-solution for an inconsistent system (2018) | **live** |
| `solve` returns `null` with an unhelpful downstream error (2019, RR) | **live** |

@mikestillman noted in 2016 that many LU-based routines were "incorrectly calling routines
meant only for fields" and that other rings still needed revisiting. The consistency check
appears to be the piece that never landed: the answer is computed, and nothing verifies it
solves the system before returning it.
