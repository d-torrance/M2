Still open on 1.26.06-40 — the original report reproduces byte for byte, and `sort` still
alternates with period two rather than converging:

```
i1 : L = {set{1,3}, set{0}, set{2}}
o1 = {set {1, 3}, set {0}, set {2}}

i2 : sort L
o2 = {set {2}, set {0}, set {1, 3}}

i3 : sort sort L
o3 = {set {1, 3}, set {0}, set {2}}

i4 : sort sort sort L == sort L
o4 = true
```

@aarondall's 2017 diagnosis is still the right one — `set{1,3} <= set{0}` and
`set{0} <= set{1,3}` are both `false`, and `set{0} ? set{1,3}` is `incomparable`, so `sort`
is being asked to totally order elements a partial order does not relate.

@pzinn's 2020 proposal in this thread — a stable, idempotent sort for an arbitrary preorder —
was never taken up, and nothing has been added since that gives a stable variant. That
suggestion, and @DanGrayson's question above it ("Can merge sort be made stable in the
presence of incomparable pairs?"), are still the open part of this issue.

### One sub-thread here *has* been resolved, which is worth recording

The `Set == Set` discussion between @DanGrayson and @pzinn was about #1185, and that is
fixed. `m2/set.m2:62` now carries

```m2
VirtualTally == VirtualTally := (x,y) -> (x ? y) === symbol ==
```

added by @pzinn in **#2918** ("VirtualTally improvements, minor expressions fixes", merged
2023-08-30) — three years after he wrote here that he was "happy with the `VirtualTally`
comparison code". So `set{1,2,3} == set{3,1,2}` is now `true` and `set{1,2} == set{1,3}` is
`false`, where in 2020 both raised *no method for* `==`.

That change also quietly altered the example @DanGrayson gave here. His line printed
`incomparable` in 2020; today it prints `false`:

```
i5 : set {ideal (0,0)} == set{ideal 0}
o5 = false

i6 : ideal (0,0) == ideal 0
o6 = true

i7 : set {ideal (0,0)} ? set{ideal 0}
o7 = incomparable
```

Because `==` is now defined as `(x ? y) === symbol ==`, it inherits whatever `?` says, and
`?` still reports these two sets as incomparable. So the thing @DanGrayson said he had
"been holding out for" — sets of mathematically equal ideals comparing equal — is
**not** delivered by that fix; only the return type changed, from `incomparable` to `false`.
Anyone reading this thread should not take #1185 being fixed as covering it.

### Summary of what is left here

- `sort` on a partial order is not idempotent. Unchanged since 2017.
- No stable sort variant exists; @pzinn's algorithm from this thread was never merged.
- Set equality of mathematically-equal-but-differently-presented members is still
  unavailable, because `?` on such members returns `incomparable`.
